# TASlation 詳細マニュアル

English: [MANUAL.md](MANUAL.md)

日常の操作は、アプリの「メニュー > ヘルプ > 使い方...」で読めます。ここには、設定やコマンドラインなどの詳しい説明をまとめています。

TASlation のリアルタイム翻訳では、本をビューアでそのまま読み、そこでめくったページの一つひとつに、ビューアのウィンドウの上であなたの言語の写植が重なります。
アカウントは不要で、訳せるページ数に上限はありません。本の内容は何もこのパソコンの外に出ません。ページの読み取りも翻訳も、このパソコンの中で行います
（「オフラインで動くことを自分で確かめる」参照）。

## 使い方

1. 本をビューアで開き、翻訳を始めたいページを表示します。
2. スタートメニューの「TASlation」から起動します。TASlation は画面に自分のウィンドウを持ちません。ビューアのウィンドウの上に写植を重ね、
   ページの横のビューアの地の部分に左右2つのペインを置きます（「左右のペイン」参照）。
3. TASlation はビューアのウィンドウを自分で探します。ストアやビューアの名前を一切持っていないので、このパソコンで初めて使うビューアは自動では選ばれません
   （タイトルに「book」「電子書籍」「本棚」などの語があるウィンドウだけは自動で選びます）。そのときは小さなダイアログが出るので、「ビューア」欄でビューアのウィンドウを選びます。
   一度選ぶと、次からは同じビューアのウィンドウが、TASlation の後に開いた場合も自動で選ばれます。「メニュー > ビューア...」でこのダイアログをもう一度開けます。
   ビューアらしいウィンドウが複数あるときは自動では選ばず、ダイアログが出ます。ブラウザのウィンドウはブラウザの名前を除いたタブのタイトルで判断し、
   「book」などの語や覚えたビューアの名前が長い語の一部にすぎないタイトルはビューアとみなしません。ブラウザのリーダーでは、
   タブやアドレスバー、リーダー自身の枠を除いたページの部分を自動で見つけ、そこだけを読みます。うまくいかないときは左のペインの「範囲設定...」で一度だけ、
   表示された画像の上でページの周りに矩形をドラッグしてください（ウィンドウごとに記憶します）。設定した範囲は外枠として扱い、
   その中でもページの部分を探して読みます（見つけた部分は破線で表示します）。矩形は8つのハンドルで大きさを変え、内側のドラッグで移動、
   外側のドラッグで描き直せます。Enter で確定、Esc で取り消し、「範囲解除」で自動で探す状態に戻ります。
4. ビューアでそのまま読みます。ページはビューアの中で、ビューア自身のキー、ボタン、クリックでめくってください。TASlation はビューアにキーを押すこともクリックを送ることもせず、
   自分からページをめくることもなく、ビューアが表示しているページだけを読みます。「自動」は最初からオンで、めくったページごとに翻訳するか、キャッシュから写植します。
   左のペインの「翻訳」は表示中のページを手動で処理します（キャッシュにあればそこから写植します）。その行の右端の丸い矢印は、
   キャッシュを使わずに訳し直します（「編集: ページを直す」参照）。OCR モデルの読み込み中などに「翻訳」を押した場合は、処理できるようになってから実行します。
   「写植」をオフにすると TASlation の写植を隠してビューアのままのページを見せ、オンに戻すとまた表示します。

写植は、クリックもキーも受け取らない専用のウィンドウにあり、ビューアのウィンドウに重なっています。クリックとキーはすべて、TASlation がないときと同じくビューアに届きます
（「編集」がオンのときは、ページの領域の枠がその上のクリックを受け取ります。「編集: ページを直す」参照）。写植の一つひとつは、それを作った元の画素に属していて、
ビューアがその場所にまさにその画素を表示しているあいだだけ見えます。ページをめくると、新しいページの最初の画像で前の写植は消えます。
ビューアがページの上に何か（バー、メニュー、パネル）を描いたところや、ほかのウィンドウが重なったところでは、そこの写植を出しません。
キャッシュにそろっているページは、ビューアが表示した時点でキャッシュから写植します。
ただし、先にぼやけた画像を描いたことのあるビューアでは、ぼやけた画像はそのままにし、鮮明な画像が届いた時点でキャッシュから写植します
（ぼやけた画像の上では吹き出しの一部しか見つからず、訳文の位置もずれるためです）。「編集」がオンのときは、
画像が落ち着いてから（0.4秒間新しい画像が届かなければ）そのページをもう一度読み、キャッシュにない吹き出しを補います。
ビューアが前面にあるあいだは、ビューアが新しい画像を描くたびに確かめ（それとは別に0.7秒ごとにも確かめます）、ほかのプログラムが前面にあるときは確かめません
（移動、大きさの変更、タブの切り替えの後には一度確かめます）。どのウィンドウが前面かは Windows が知らせるので、ほかのウィンドウの中身は読みません。
`taslation.toml` で `follow = "poll"` とすると、常に0.7秒ごとに確かめます。
待つべき画像（読み込み画面、見開きの半分、薄い下見の画像）では何も始めません。ビューアがページの上に自分のバー（ツールバーやページのスライダー。
多くのビューアは少しすると自分で隠します）を出しているあいだは、バーが3.5秒出たままになってから、その行を除いてページを読みます。バーが消えたら、
バーにかかっていた吹き出しを読み直します。
キャッシュにないページも、画像が落ち着くのを待たずに、最初の新しい画像から読み始めます。
読み終えたら、画像がまだ変わっていないことを確かめてすぐにモデルへ翻訳を頼み、答えを待つあいだも画像を見続けます。訳をキャッシュに残すのは、
画像が0.8秒間（設定 `settle_ms` の値の2倍。どのビューアでも同じ）変わらなかったときだけです。
それまでに画像が変わると（ページがすべり込む、ぼやけた画像が鮮明な画像に替わるなど）、頼んでいた翻訳を止め、その画像から読んだものは捨て、
新しい画像から読み直します。
それより後でぼやけた画像が鮮明な画像に替わったときも、ぼやけた画像から残したものは捨てます。その翻訳がまだ続いているあいだと、
ぼやけた画像を先に描いたことのあるビューアでは翻訳を終えてから2秒のあいだです。
`taslation.toml` で `early_start = false` とすると、以前の版と同じく、画像が `settle_ms` のあいだ変わらなくなってから読みます。
翻訳中に別のページへめくると、新しいページはビューアが描くとおりにすぐ見え、前のページの写植は重なりません。前のページの翻訳を止めるのは、
新しい画像が少しのあいだ（0.15秒）変わらなかったときだけです（黒い画面や読み込み中の表示では止めず、そのページに戻れば写植がまた見えます）。
止めたあと、新しいページを読みます。訳し終えて表示しているページが次に見せるための準備をしているだけのときは、すぐに止めます。
止めたページでそれまでに訳せた吹き出しは、まだ終わっていないページとしてキャッシュに残ります（上と同じく、画像が0.8秒変わらなかったページだけです）。
そのページに戻ると、それらはすぐに写植され、残りだけを読んで訳します。左のペインの「停止」で止めたページは何も残しません。

未訳のページは、見ている間に埋まっていきます。ページの吹き出しを読む順に、前の台詞を文脈にして訳させます。訳ができた吹き出しから写植します。
台詞は読み取ったそばから翻訳に回すので、ページ全体を読み終える前に最初の吹き出しが写植されます。ページを読み終えたあと、そうして早く訳した吹き出しが
訳し直されることがあります（読む順が違っていたときなど）。そのときは一瞬写植のない状態になり、写植し直します。最後に、
シリーズ設定と違う綴りの名前を機械的にそろえるので、いくつかの吹き出しが変わることがあります。吹き出しに収まらない訳は、文字を小さくして組みます
（モデルに短くさせることはしません）。
右のペイン（「インジケーター」がオンのとき）に、ページがどこまで進んだかを出します（「このページ: 7 行中 3 行」）。ページを見てから1秒たっても吹き出しが1つも写植されていないときだけ、
「モデルを読み込んでいます...」「ページを読み取っています...」「翻訳中...」のどれかも出し、最初の吹き出しが写植されると消します。訳せなかったページでは、
そのページを表示しているあいだ「このページを翻訳できませんでした。」を出し（「翻訳」でもう一度試します）、読み取るものがないページでは「このページには読み取るものがありません。」を4秒出します。

### 左右のペイン

TASlation の操作と表示は、ページの横のビューアの地の部分、取り込み範囲の左右の端にある2つのペインにあります。
色はその地に合わせ（暗い地には明るく、明るい地には暗く）、大きさはビューアのモニターの拡大率に合わせ、ビューアのウィンドウと一緒に動きます。

* **左のペイン** は操作です。「翻訳」（ページを翻訳しているあいだは「停止」）とその行の右端の丸い矢印（表示中のページを訳し直します）、
  「自動」、翻訳先の言語（左右に矢印。1秒ほど矢印をクリックしなければ、その言語に決まります）、「写植」、「インジケーター」、「編集」、
  「範囲設定...」、「設定...」、「メニュー」、「終了」です。操作をクリックしてもキーボードがビューアから離れることはなく、行と行のあいだのクリックはビューアに届きます。
* **右のペイン**（「インジケーター」がオンのとき）は表示です。いちばん上に最後にポインターの下にあった吹き出し（「ポインターの下の吹き出し」参照）、その下に準備の行
  （何が足りずどう直すか）、表示中のページの進み具合、ステータス行、めくったページの残り、翻訳が GPU とプロセッサーのどちらで動いているかが出ます。
  クリックは、吹き出しの3つのボタンを除いてビューアに届きます。「インジケーター」をオフにすると（「設定...」の「ビューアの右にインジケーター」、`see_through_indicators`）
  右のペインは出ず、準備の行は、伝えることがあるあいだ専用の小さなダイアログに出ます。
* **「メニュー」** はそのほかです。「ビューア...」「シリーズと巻...」「保存した翻訳...」「複数の訳し方をされた名前...」「モデルを今すぐ解放」、
  「言語」と「ヘルプ」（「使い方...」「法的な注意事項...」「更新を確認...」「TASlation について」）があります。「編集」がオンのあいだは、編集の項目が先頭に並びます（「編集: ページを直す」参照）。
  準備に TASlation が代わりに直せるものがあるあいだは（「翻訳プログラムを起動し直す」「モデルをダウンロード」「ビューアを表示」）、そのボタンがメニューの先頭に来ます。

ペインにはページの横に余地が要ります。ページに近づいてしまうペインや、ビューアの地が短すぎるペインは、ページを覆う代わりに隠れます
（1920 x 1080 のウィンドウの見開きの横には余地があります。狭いウィンドウや横長のページの横には、ないこともあります）。ビューアが最小化されているときや隠れているとき、
ほかのウィンドウがペインに重なっているところでも、ペインは隠れます。左のペインに余地がないあいだは、タスクバーの TASlation のボタンをクリックすると、ポインターの位置にメニューが開き、
左のペインの操作（「翻訳」「自動」「写植」「範囲設定...」）と「設定...」「終了」も加わります。タスクバーのボタンは、いつでもこのプログラムへの入り口です。
そこで閉じると（ボタンのメニューから、または Alt+F4 で）、「終了」と同じく TASlation が終わります。

TASlation のダイアログは、ビューアの上、ビューアのモニターに開きます。自分で開いたダイアログは開いているあいだキーを受け取り、閉じるとキーはビューアに戻ります。

### ポインターの下の吹き出し: 原文と日本語のコピー

吹き出しの上にポインターを置くと、少しして（`hover_delay_ms`、既定は 450 ミリ秒。「設定...」の「ポインターの下で待つ時間」で 0 から 3000、0 ならすぐ）、
その吹き出しの写植が消え、その場に元の写植が見えます。ポインターが吹き出しを離れると、写植が戻ります。
ポインターは位置を読むだけです。キーボードはビューアのままで、そこでのクリックもこれまでどおりビューアに届きます。

「インジケーター」がオンなら、右のペインのいちばん上にその吹き出しが出ます。「日本語をコピー」「訳文をコピー」「もう一度訳す」のボタン、その下に日本語と訳文
（それぞれ5行まで）です。ポインターがペインへ移れるよう、ポインターが吹き出しを離れても残り、別の吹き出しにポインターを置くか、ビューアが別のページを表示すると替わります。
「もう一度訳す」は、その吹き出しの台詞だけをあらためて翻訳に頼み、答えを写植します（自分の修正ではなく、モデルの答えとして扱います）。
右から左へ書く言語や、字形を組み合わせて書く言語（アラビア語、ヘブライ語、ヒンディー語、ベンガル語）が翻訳先のときは、訳文をペインに出しません。それでも「訳文をコピー」でコピーできます。

この回に読んだページなら、日本語はメモリにあります。キャッシュから表示したページには日本語がないので（キャッシュに日本語は保存しません）、その吹き出しがペインに少し（0.3秒）出たところで、
メモリ上の取り込みからその吹き出しの部分を読み直します。読んだ日本語はページと一緒にメモリに置くだけで、ディスクにもログにも書きません。
クリップボードに書くのは、コピーのボタンを押したときだけです。コピーした本の一行は、別のものをコピーするまでクリップボードに残り、ほかのプログラムからも読めます。

### めくったページ

読んでいるあいだ、めくって通り過ぎたページも、TASlation が後ろで読み取りと翻訳を続けます。
この作業は、お使いのほかのプログラムより低い優先度で動きます。ページをめくる操作と、いま開いているページが先になります。
右のペインに、残りのページと行の数と、めくるのが速すぎて取り込めなかったページの数が出ます。そうしたページは、ビューアでそこへ戻れば、ほかのページと同じように読み取ります。
後ろで済んだページに戻ると、ビューアが表示したとたんに写植されます。
TASlation がメモリにあるページを読むためのページとして表示することはなく、ビューアにも何も送りません。

### 画面1つで、ビューアの全画面でも

2台目のモニターは要りません。TASlation はビューアそのものの上に重なります。
ビューアはどんな大きさのウィンドウでも、最大化しても、ビューア自身の全画面でもかまいません（全画面にはビューアの中でご自分で切り替えてください。TASlation が切り替えることはありません）。写植とペインはそれについていきます。
TASlation がビューアのウィンドウを動かしたり、大きさを変えたりすることはありません。ペインには、ページの横のビューアの地が少し要ります（「左右のペイン」）。

読んでいるあいだは、ビューアの一部が見えるようにしておいてください。ほかのウィンドウに完全に覆われると描画をやめるビューアがあり、ブラウザも不透明なウィンドウに完全に覆われると描画をやめます。
そのあいだはページを読めません（「ビューアの読み取り方」参照）。

### 本を読み始めるとき: 準備と書名

ページは開いたときに、直前の数ページだけを文脈にして訳します（「自動」と「翻訳」の動作です）。めくって通り過ぎたページは、後ろで読み取りと翻訳を続けます（上の「めくったページ」）。

翻訳に要るものが足りないとき（Ollama が動いていない、モデルや OCR モデルが入っていない）は、
何が足りずどう直すかを右のペインに表示し、直るまで10秒ごとに確かめ直します（「インジケーター」がオフなら、小さなダイアログで伝えます）。

**準備の行のボタン**。TASlation が代わりに直せるものなら、その行にボタンが付きます。ボタンはメニューの先頭（と小さなダイアログ）に並びます。

| 表示 | ボタン | 押すと |
|---|---|---|
| 翻訳プログラム（Ollama）が動いていない | 翻訳プログラムを起動し直す | その場で Ollama を起動し、設定を確かめ直します |
| 翻訳先に要る翻訳モデルが入っていない | モデルをダウンロード | 大きさを示してダウンロードを尋ねます（前に「今はしない」と答えていても尋ねます） |
| ビューアのウィンドウが最小化されている | ビューアを表示 | ビューアを元の大きさに戻します（キーは押さず、フォーカスも移しません） |
| ビューアが真っ黒なまま | ビューアを表示 | ビューアのウィンドウをほかのウィンドウの手前に出します。本をクリックして再読み込みしてください |

起動したときに翻訳がプロセッサー（CPU）で動くとわかれば（Ollama のログに書かれたグラフィックカードの有無で判断します）、
1ページの翻訳にかかるおおよその秒数を右のペインに一度だけ表示します。メニューのその「閉じる」で、そのセッションのあいだは消えます。

ビューアのウィンドウのタイトルから本の名前がわからないときは、最初のページで小さなダイアログが書名を尋ねます。
キャッシュとシリーズ設定はこの名前で保存されます。ブラウザで読むビューアには、どの本を開いてもタブのタイトルがビューアの名前だけのものがあり、
そうしたタイトルでは必ず尋ねます（ビューアやブラウザの名前を書名にすることはありません）。
タイトルのうちビューアの名前の部分は、このパソコンで覚えます。同じビューアで2冊目の本を選んだとき、または「メニュー > シリーズと巻...」でタイトルからビューアの名前を除いた書名を入力したときに覚え、以後はその部分を書名に含めません。最初の1冊はタイトル全体が「シリーズ」欄に入ることがあるので、そのときは書名を直してください。タブのタイトルがビューアの名前だけのブラウザのビューアでは最初に書名を尋ね、答えた書名から、そのタイトルが本の名前でないことを覚えます。
覚えた内容（ビューアとして選んだウィンドウのタイトルとプログラムのファイル名、タイトルのうちビューアの部分と本の部分）は、このパソコンの `~/.taslation/viewers.json` にだけ保存されます。キャッシュの書き出しにもログにも入らず、どこにも送られません。このファイルを削除しても、ビューアを一度選び直すだけで元に戻ります。
一度名前を付けた本は、どの取り込み範囲で読んでも翻訳済みのページから見分け、名前を入れておきます。複数の本が似ていれば欄の一覧に候補を出し、
見分けられなければ、同じビューアで前回付けた名前を入れておきます（「このビューアで前回読んだ本: ...」）。
ビューアのウィンドウの大きさを変えても、次に開いたとき本はページから見分けられます（見開きの2ページがそろって同じ本の別々のページに近ければ、その本と判断します）。古いキャッシュも当時のページの切り出し方で照合するので、そのまま使えます。
名前を入れずにダイアログを閉じると何も読み取らず、名前なしでは何も残せないので、次のページでもう一度尋ねます。

訳したページは、同じ人物の名前が訳文の中で複数の書き方になっていないかも確かめます（「竜司」が「Ryuji」と「Ryūji」に分かれている、など）。
「メニュー > 複数の訳し方をされた名前...」が、そうした名前を一覧にします。
名前ごとに書き方とその行数が並ぶので、残す書き方を選ぶか「その他:」に入力して「適用」を押すと、ほかの書き方の行をその書き方にそろえます。
「シリーズ設定に残す」にチェックがあれば（既定）、シリーズ設定の登場人物の表記にも入れ、以後の翻訳はその書き方を使います。
「適用」を押すまで何も変えません。変えるのは日本語にその名前がある行の、その名前の部分だけで、ほかの部分、要確認の印、訳注、位置はそのまま残ります。
ダイアログの「元に戻す」で、行もシリーズ設定も元どおりにします（「編集」がオンなら、メニューの「元に戻す」で行だけを戻すこともできます。そのあとダイアログの「元に戻す」を押すと、シリーズ設定も戻ります）。
見つけ方は決まった規則によるもので、モデルは使いません。日本語で「さん」「くん」「様」などの敬称が付いている名前（カタカナ2字以上、または漢字2～4字）だけを対象にし、
訳文に2通り以上の書き方があり、それぞれが別々の行にあって、同じ名前の書き方らしいときだけ出します（間違った提案をするより、見逃すほうを選んでいます）。
大文字のない言語（中国語、韓国語、タイ語など）の訳文では出ません。
日本語の行は TASlation を開いている間メモリに置くだけで、どこにも書きません。そのため対象は、このセッションで訳したページの行だけです（最大で約3,000行、古いものから消えます。キャッシュから表示しただけのページには、確かめる日本語がありません）。

モデルがしばらく何も返さないと、TASlation はもう一度頼み、右のペインにそう表示します。
TASlation を開いている間は、画面も消えず、パソコンもスリープしません（画面が消えるとビューアが描き直しをやめるためです）。
ふたを閉じる、手動でスリープする、ロックするといった操作までは防げません。TASlation を終了すれば元に戻ります。

以前のバージョンで1冊まるごと先に読んで保存した訳文もキャッシュに残り、ほかの訳したページと同じように表示します。

### ビューアの読み取り方

ビューアの画面は Windows.Graphics.Capture で取得します。ウィンドウがほかのウィンドウの裏にあっても読み取れ、取得した画像はメモリ上の最新の
1枚だけで、ディスクには保存しません。使えない環境では自動的に PrintWindow に切り替わります（どちらを使っているかは `taslation doctor` に
表示されます）。ディスプレイの電源が切れると描画が止まるので、TASlation を開いている間はディスプレイをつけたままにします。

TASlation はビューアのウィンドウを、そのままの大きさで読みます。動かすことも大きさを変えることもなく、キーも押しません。ビューアのウィンドウは大きいほどよく読み取れます。
1.0.1 までの版は、モニターの作業領域より小さいビューアのウィンドウを広げていました。そうした版が広げたまま残したウィンドウ（閉じずに終わったとき）は、
広げた大きさのままなら、次の起動で元に戻します（状態フォルダの `ui.json` に覚えています）。
キャッシュにあるページを表示するときは、ステータス行に「翻訳中...」ではなく「ページを確認中...」と表示します。

隠れている間は描画を止めるビューアもあります。ビューアを選んだとき、ビューアがほかのウィンドウに完全に隠れていれば、
TASlation はキーを押さずに描き直しを頼み（ほかのウィンドウをどけたときに Windows が頼むのと同じものです）、隠れたままでも描くかどうかを確かめて、
ビューアごとに `profiles.json` に記録します。何も届かなければ、ビューアを一瞬だけ手前に出して確かめ（キー入力やフォーカスの移動はありません）、
すぐ元の順序に戻します。ほかのウィンドウが重なったまま、ビューアの画像が3秒（`page_turn_wait_ms`）空のままだったときも、同じように一度確かめます。
覆われているあいだ何も描かないビューアは、右のペインにそう表示するので、一部が見えるようにしておいてください。一部でも見えているビューアは描画を続けます。
ブラウザは、不透明なウィンドウに完全に覆われたときだけ描画を止めるという公開されている決まりに従うので、確かめることはしません。

### ビューアが真っ暗なままのとき

ブラウザで読むビューアは、読み込み画面のまま止まったり、画面が黒いままになったりすることがあります。取り込む範囲が黒いままだと、TASlation は次のようにします。キーは一切押しません。

1. **待つ**: 読み込みが遅いだけかもしれないので、`black_wait_s`（既定 30 秒）待ちます。約 8 秒たつと「まだ読み込み中」と表示します。
   この間は 1 秒に 1 回ほど、新しいフレームが届いたかどうかをメモリ上で確かめるだけです（PrintWindow で取り込んでいるときは 2 秒に 1 回取り込みます）。
2. **知らせる**: それでも黒いままなら、本のウィンドウで再読み込みするよう、右のペインで一度だけ伝えます。本をクリックしてから、そのウィンドウの再読み込みキー
   （ブラウザなら F5）を押してください。メニューの「ビューアを表示」で、ビューアのウィンドウをほかのウィンドウの手前に出せます。

TASlation はそのまま待ち、ページが表示されれば、そのとき表示されているページから続けます。黒い画面を翻訳したりキャッシュしたりすることはありません。本当に真っ黒なページは読み込みが止まった画面と区別できないため、同じ扱いになります。

### 書名: シリーズと巻

本の名前は「シリーズ」と「巻」の2つの欄で入力します（「メニュー > シリーズと巻...」、本を読み始めるときのダイアログ、奥付による書名の提案）。
訳文・ページに付けた情報・シリーズ設定は、この2つからできる1つの書名で保存されます。つなぎ方が1通りなので、
「3巻」「３」「第三巻」と書き方が違うだけで別の本になることはありません。

* シリーズ: 各巻に共通の名前です。「完全版」などの版もここに含めます。シリーズ設定はこの名前で保存されます。
* 巻: 番号です（半角数字、先頭の 0 なし。10.5 のような小数も使えます）。全角数字、①や❸のような丸数字、一〜九百九十九の漢数字でも入力でき、
  「第3巻」「3巻」「Vol. 3」「#3」「(3)」はどれも 3 になります（欄を離れると、保存される書き方に直ります）。
  番号でない巻は 上・中・下・前編・後編 だけです（上巻・前篇などは同じものとして扱います）。それ以外は受け付けず、理由を表示します。
  1冊だけの本は空欄のままにします。
* 書名は「シリーズ 巻」（半角スペース1つ）、巻が空ならシリーズだけです。全角の英数字は半角に、続いた空白は1つにまとめます。

ビューアのタイトルや以前のキャッシュの名前のように1つの文字列で来た書名は、末尾の巻（上の書き方のほか、「(見本コミックス)」のような
レーベルの前にある巻も）を見つけて2つの欄に分けます。区切りなしで数字で終わるタイトル（「Some Title13」など）、巻の印のない
4桁の数字（年など）、前に巻のない括弧はタイトルの一部として残します。分け方が違っていたら欄を直してください。直した分け方
（たとえば「Gate 51」をシリーズ名にして巻は空）はこのパソコンの `~/.taslation/ui.json` に覚え、以後その書名はそのとおりに扱います。

この版より前に「Some Title 3巻」のような書き方で保存した訳文は、欄が「Some Title」と「3」でもそのまま見つかり、元の名前で読み書きします
（シリーズ名と巻が同じなら同じ本です）。名前が勝手に変わることはありません。そのような本は、起動するたびに一度だけ、
1通りの書き方への書名の変更を提案します。「書名を変更」を選ぶと、奥付による書名の変更（次の節）と同じように訳文・ページに付けた情報・
シリーズ設定を移します（シリーズ設定が食い違えば、先に確認の表を出します）。「今はしない」なら元の名前のまま、これまでどおり使えます。
本ごとの「編集」のオン・オフも、書名を変えたあとまで引き継ぎます。以前の版が漢数字の巻（「第一巻」など）を含む書名を
まるごとシリーズ名にしていたシリーズ設定も見つけて使い、書名を変えるときに一緒に移します。

コマンドラインでは `--series` と `--volume` で同じように書名を指定できます。`--book` の書名は1つの文字列として同じ規則で分け、
1通りの書き方にします（以前の書き方で保存した訳文があれば、その名前で読み書きします）。

### 奥付と書名の変更

巻の終わり近くで、TASlation は奥付（書名、巻、著者、出版社、ISBN）を読み、キャッシュのヘッダーに保存して、
奥付による書名を本ごとに一度だけ提案します。書名は「シリーズ」と「巻」の欄に入れて示すので、違っていれば直せます。「使う」か「今のまま」を選びます。

本の今の名前（最初に入力した名前や、ビューアの名前のまま保存した古いキャッシュ）でファイルがあるときは、「使う」で書名を変えます。
全言語の訳文とページに付けた情報を、新しい名前が別のシリーズに属するならシリーズ設定も、新しい名前に移し、
何をいくつ移したかをステータス行に表示します。

そのシリーズにすでにシリーズ設定がある場合（前の巻をフルタイトルに変えた場合など）は、この本のシリーズ設定をそこに統合します。
追加される内容はそのまま取り込みます。食い違う箇所（用語の表記、人物の一人称、文体ガイドの方針など）は、
何かを移す前に1件ずつシリーズの値とこの本の値を並べて表示するので、
「シリーズの方を残す」か「この本の方を採用」を選びます（まとめて選ぶこともできます）。「書名を変更」でその答えのとおりに書名を変え、
「キャンセル」なら書名はそのままで、奥付の書名は次回また提案します。この表は「編集」がオンのときだけ出ます。オフのときは尋ねず、どの行もシリーズの方を残して統合します。
答えることがなければすぐに統合し、追加した件数、この本の方を採用した件数、シリーズの方のままにした件数を表示します。

新しい名前が別のシリーズに属するときは、シリーズの既定値（「この本の設定...」を参照）も移ります。新しいシリーズにまだ既定値がなければ、元のシリーズの既定値をそこへ移し、
元のシリーズにほかの巻がまだ保存されているときは、その巻が使い続けられるようにコピーします。新しいシリーズにすでに既定値があれば、それはそのまま残し、元のシリーズの既定値も残します。
シリーズに従っていた本は、それまで使われていた値を保ちます。新しいシリーズの既定値（巻数のない名前なら既定値なし）で値が変わってしまう場合は、
元のシリーズから受け継いでいた値をこの本自身の値にして、シリーズには従わなくなります。

それ以外のものは上書きしません。新しい名前の訳文やページに付けた情報がすでにある場合は何も移さず、
邪魔になっているファイルを示します。

### TASlation の言語

初回の起動時に、どの国にいるかと TASlation の言語を尋ね（「起動時の注意事項」参照）、`~/.taslation/notice.json` と
`~/.taslation/ui.json` に記憶します。言語は「メニュー > 言語」でいつでも変えられ、
国は「メニュー > ヘルプ > 法的な注意事項...」で変えられます。`--ui-language ja` や設定ファイルの
`ui_language` で指定することもできます。

組み込みの言語は17種類です: English、日本語、Español、Português (Brasil)、Français、Deutsch、
Italiano、Nederlands、Polski、Русский、Türkçe、Bahasa Indonesia、Tiếng Việt、简体中文、
繁體中文、한국어、ไทย。これはペイン、メニュー、ダイアログ、メッセージの言語で、訳文の言語ではありません。訳文は左のペインの言語の行にある20言語のどれにでもできます。
「メニュー > ヘルプ > TASlation について」には、バージョン、ライセンス、
キャッシュ・シリーズ設定・設定を保存するフォルダ、README と docs/THIRD_PARTY.md の場所があります。

### 編集: ページを直す

左のペインの「編集」で、編集のオン・オフを切り替えます。本ごとに最後の状態を覚えます（まだ選んだことのない本はオフで始まり、
`--role translator` や設定ファイルの `role = "translator"` ならオンで始まります）。「編集」がオンのあいだは、表示中のページの領域がビューアの上に枠で出て、
それぞれに読み順の番号がその色の小さな札で付きます（緑: 訳済み、オレンジ: 未訳、青: 自分で指定した領域、
赤: 訳済みだが要確認）。枠の外のクリックはこれまでどおりビューアに届き、キーも、TASlation のダイアログ（領域の編集画面を含む）が開いているあいだを除いてビューアに届きます。

* **枠の上のマウス**: 枠をクリックすると、その横に領域の編集画面が開きます。オフィスソフトの図形のように、ドラッグで動かし、角のハンドルで大きさを変えられ、
  新しい枠がより広い範囲を含むときだけ読み直します（ドラッグ中に右クリックすると、ドラッグを取りやめます）。Shift+クリックで、枠を選んだ領域に加え、
  またはそこから外します。選んだ領域の1つをドラッグすると、全部まとめて動きます（どれかがページの端に着いたところで全体が止まります）。ポインターの下の枠は、
  原文に譲る代わりに角のハンドル付きで縁取られ、右のペインにその言葉が出ます。
* **マウスホイール**: 枠の上で回したホイールはビューアに届きません（Windows はホイールをポインターの下のウィンドウに渡すためです）。ビューアをスクロールするときは、ポインターを枠の外へ動かすか、「編集」をオフにしてください。
* **メニュー**: 「編集」がオンのあいだは、メニューに編集の項目があります。「元に戻す」と「やり直す」、「ページ」（「読み順」「文字の領域を追加」「このページを除外」、選んだ領域に対する
  「種別を設定...」「文字サイズを設定...」「読み順の位置を指定...」「書式のコピー」「書式の貼り付け」「この種別のすべての領域に書式を貼り付け...」「領域のコピー」「領域の貼り付け」
  「選んだ領域を削除」「この本の全ページでこの範囲を無視」、それに「この範囲をシリーズに使う」）、そして「レビュー...」「自分の修正...」「要確認の行...」
  「検索と置換...」「シリーズ設定...」「この本の設定...」で、どれもそれぞれのダイアログです。枠をクリックすると、その領域が選ばれます。

* **書式のコピーと貼り付け**: ワープロの書式のコピーと同じく、「書式のコピー」で選んだ領域の書式（フォント、サイズ、太字・斜体、
  揃え、行間・字間、傾き、文字列の方向、文字の色と縁取り）を覚え、「書式の貼り付け」でそのとき選んでいる領域にその書式を付けます
  （「元に戻す」の1回で戻せます）。種別（台詞・心の声・叫びなど）は翻訳のときにモデルに伝える前提情報なので、書式と一緒には写しません。
  「この種別のすべての領域に書式を貼り付け...」は、コピーした書式を、選んだ領域と同じ種別の、この本のすべての領域に
  付けます（件数を示して確認します。種別は本の前提情報が持っているので、まだ表示していないページの領域にも付きます。
  種別が「指定なし」のときは、訳したページの領域が対象です）。どのページを表示していても、「元に戻す」の1回で全体を元に戻せます。
  「領域のコピー」は選んだ領域そのもの（枠と書式）を覚え、同じレイアウトの別のページで「領域の貼り付け」を選ぶと、
  同じ位置に領域を加えて読み取り・翻訳します（そこにすでに領域があるときや、ページの大きさが違うときは加えません）。

* **領域**: 文字領域にはすべて、番号付きの枠が付きます。検出されなかった文字を矩形で囲むと、読み取って翻訳し、
  ページに加えます（以後の読み取りでも使われます）。「文字の領域を追加」を選んでから、ページの上でドラッグします（ドラッグせずにクリックすると取りやめます）。
  絵の上では、矩形の中の文字だけを消して下の絵を埋めます（インペイントのモデルが動くときはモデルで、そうでなければ文字の周りの絵から）。
  吹き出しの中や平らな箱の上では、矩形をその紙の色で消し、輪郭線とその外の絵は残します。
  傾きは領域の編集画面（「傾き」）で決めます。傾けた領域は、動かしても大きさを変えても傾きを保ちます。
  「選んだ領域を削除」で消した領域は、そのページで「文字ではない」と記憶されるので、誤検出が戻ってくることはありません。
* **全ページで無視する範囲**: 透かし、ノンブル、毎ページの帯のように、どのページでも同じ場所に出て訳したくないものは、その領域を選んで
  「この本の全ページでこの範囲を無視」を選ぶと、その場所（領域の枠を少し広げた範囲）を本の全ページで無視します。
  ほかのページで削除したのと同じ場所の領域を削除したときも、削除を保存したあとに同じことを尋ねます（「このページだけ」と答えた場所は、
  TASlation を閉じるまで二度と尋ねません。自分で追加した領域を削除したときは尋ねません）。範囲にほぼ（面積の 70% 以上）収まる検出は、
  見つからなかったものとして扱い、描かれたまま残します。自分で追加した領域は範囲の中でも残ります。
  見開きのページで決めた範囲はその側（右か左）のページと1ページずつ表示したページに、1ページずつ表示したページで決めた範囲はすべての
  ページに当てはまり、形の大きく違うページ（見開きを1枚の画像にしたものなど）には当てはまりません。追加はどのページを表示していても
  「元に戻す」の1回で元に戻せます。範囲の中の訳文はキャッシュに残るので、元に戻すとそのまま戻ります。保存するのは範囲の4つの数値、
  見開きの側、ページの縦横比だけです。
* **領域の編集**: 枠をクリックすると、その横に開きます。書式の欄は、その領域に書式の指定がなければ「書式」のボタンの中に畳まれています。**話者**（シリーズ設定の名前から選べます）、**種別**（台詞、
  心の声、叫び、ナレーション、効果音、手書き、消去のみ）、**文が次の吹き出しに続く** かどうか、**モデルへのヒント**（言葉遊び、誰に向けた台詞か）、
  訳文を変えられます。Enter で改行し（写植でもその改行を守ります）、Ctrl+Enter で保存します。
  PLaMo 3 Translate（ブラジルポルトガル語とトルコ語以外の翻訳先のモデル。「モデルの選び方」を参照）がヒントに従うのはときどき（試験ではおよそ半分）なので、編集画面のヒントの下にそう表示します。
  よく効くのは名前や用語の読み方と、誰のことか・いくつのことかです。いつも同じ訳にしたい名前と用語はシリーズ設定に入れてください。Qwen3.5 4B や自分で選んだモデルには、ヒントを吹き出しと一緒に渡します。
  ヒントは、その必要がないところでもその行の言い回しを変えることがあります。ただしほかの行には届きません。次の吹き出しと1つの文としてまとめて訳す要求にはヒントを入れず、「もう一度訳す」はその吹き出しだけをヒント付きで訳します。
  種別を「消去のみ」にすると、その領域の元の文字を消すだけで、そこには何も写植しません（選ぶとすぐ、ビューアの上の写植に消した姿が出ます）。
  翻訳には送らず、要確認にも未訳にも数えません。前の訳文はキャッシュに残るので、種別を戻せばまた写植されます。
  変更は「元に戻す」で元に戻せます。
  原文で吹き出しの一部がほかより大きく書かれていて、その部分が訳文の中で見つかったとき（「設定...」の `size_emphasis`）、訳文の欄ではその言葉が大きく表示されます。
  入力に合わせて位置が動き、その言葉に触れる編集をすると、吹き出しはまた一つの大きさで写植されます。書式バーの「大きくする」と「大きさをそろえる」で設定・解除できます。
  「もう一度訳す」の新しい答えでも、その部分を探します。
  編集画面の上には、取り込んだ画面から切り出したその領域の元の姿が出ます（メモリ上だけの画像で、どこにも保存しません）。「原文を表示」を押しているあいだは、
  その領域の写植の代わりにビューアの原文が見えます。
  キャッシュから表示したページは日本語を持たないので（キャッシュは訳文しか保存しません）、「日本語を読み取る」でその場で読み直すと、
  「読み取り結果:」が出て「もう一度訳す」も使えます（読み取っていないまま「もう一度訳す」を押すと、先に読み取ります）。
  日本語の読み間違いは「読み取り結果:」の欄で直せます。「もう一度訳す」は直した読みを訳し、このセッション中にその吹き出しを読み直すものもすべて同じです
  （訳し直し、キャッシュからの読み直し、領域の移動）。何も読めなかったときは、読み取りのあとに欄が出るので日本語を入力できます。
  直した読みはメモリ上だけにあり、保存されません。「保存」で残るのは訳文だけで、「元に戻す」が戻すのも訳文で、読みは戻りません。
  「前へ (Alt+↑)」「次へ (Alt+↓)」で、読む順にひとつ前・後の領域の編集に移ります。変えた内容があれば、移る前に「保存」と同じく保存し
  （「元に戻す」で1回の変更として元に戻せます）、何も変えていなければ何も書き込みません。
  何かを変えたまま Esc か編集画面の閉じるボタンで閉じようとすると、変更を破棄してよいか尋ねます（「編集を続ける」が既定です）。
  「キャンセル」のボタンは尋ねずに閉じます。
* **書式バー**: 訳文の上の書式バーは、ワープロのテキストボックスのように使えます。
  「太字」「斜体」（「自動」でシリーズ設定の種別ごとの指定に戻ります）、**フォント**（このパソコンに入っているフォント。
  そのフォントがないパソコンでは自動選択のフォントを使います。一覧の先頭には、横の ☆ でスターを付けたフォント、次に最近使ったフォント
  （最後の10個）が並びます。★ をもう一度押すとスターを外します。Tab で移って Space でも押せます。覚えるのはフォントのファミリー名だけで、
  このパソコンの ui.json に保存します）、**サイズ**（「自動」は収まる最大の大きさ。固定したサイズは縮めず、
  収まらない文字は吹き出しの縁で切れ、そう表示します）、「文字幅を詰めて収める」（14ポイント未満では自動）、
  「大きくする」（訳文で選んだ言葉をほかより大きく写植します。原文の大きい部分を測れたときはその倍率、測れなかったときは 1.5 倍です。欄でも大きく表示されます）と「大きさをそろえる」（訳文全体を一つの大きさにします）、
  左揃え・中央揃え・右揃えと上揃え・上下中央・下揃え、**行間**、**字間**、**傾き**（反時計回りの角度。「自動」は元の文字の傾きのまま）、**文字列の方向**（Word のテキストボックスと同じく、自動・横書き・すべての文字列を 90° 回転（上から下へ読む、英語の本の背表紙の向き）・すべての文字列を 270° 回転（下から上へ読む）・縦書き（文字を縦に積み、右から左へ列を並べます。長音「ー」やダッシュ、「…」、かっこは縦書き用の形にし、小さいかなと句読点は縦書きの位置に置き、ラテン文字は1字ずつ立てて積みます。縦中横やルビには対応していません）。傾きと組み合わせると、方向を決めた文字を枠ごと傾けます）、**文字の色**と**縁取りの色**（自動・黒・白・カスタム...。カスタムでは Windows の色の設定画面で好きな色を選び、横の色見本をクリックすると選び直せます。ネットには何も問い合わせません）、**縁取り**（自動・縁取りあり・縁取りなし）、「書式をリセット」があります。色と縁取りの「自動」は、シリーズ設定がその種別に決めた色と縁取りに従い、決めていなければ、文字は背景に合わせて黒か白、縁取りは絵やトーンの上だけ、縁取りの色は文字と反対の色になります。色と縁取りは文字の大きさや改行を変えません。「書式のコピー」（Ctrl+Shift+C）でバーの書式を覚え、「書式の貼り付け」（Ctrl+Shift+V）で別の領域の編集画面のバーに入れられます（「保存」で確定します）。
  変更すると、少ししてビューアの上の写植が追いつきます。書式は本のページ情報と一緒に保存されます。
* **シリーズ設定への反映**: シリーズ設定が別の表記にしている名前や用語を自分の編集で置き換えると、それをシリーズ設定の表記にするかを尋ね、
  すでに訳したページでも置き換えます（訳文の置き換えは1回の変更として「元に戻す」で元に戻せます。シリーズ設定の表記は戻りません）。
* 「読み順」: 自動で決めた順番が違うときは、「読み順」を選び、読む順に枠をクリックしてから、メニューの「読み順を確定」を選びます
  （「読み順の設定を取り消す」なら元の順番のままです）。分かれた文や、誰が誰に答えているかはこの順番で決まります。
  1つの領域だけ順番を直すときは、その領域を選んで
  「読み順の位置を指定...」で何番目にするかを入れます（複数を選んでいれば、その並びのままその位置に置きます。ほかの領域の順番は
  変わりません。「元に戻す」で元に戻せます）。
  「このページを除外」は、広告やビューア自身のパネルなど訳すもののないページに印を付け、丸い矢印（キャッシュを使いません）は今の前提情報でページを訳し直します。
  自分で直した訳文（編集画面や「検索と置換」で変えたもの）はそのまま残り、モデルには送りません。
  それも訳し直すときは、確認の「自分で直した行も置き換える」に印を付けます。
* 「自分の修正...」は、この本で自分で直した訳文を、保存した訳文だけからページごとに一覧にします。
  選ぶとそのページが何ページ目かを伝えます。ビューアには何も送らないので、そのページへはご自分でめくってください。
  「もう一度訳す」の答えをそのまま保存したものは自分の修正に入りません。シリーズ設定や名前の確認で綴りをそろえても、その行の扱いは変わりません。
* 「要確認の行...」は、この本で確認したほうがよい行を、保存した訳文だけからページごとにすべて一覧にします。訳したときに要確認の印が付いた行
  （理由は「レビュー...」と同じで、`taslation review` が並べるものです）と、読者への訳注がある行です。表示中のページについては、写植のチェックで
  見つかったことも載ります（これはページを写植するときに調べるもので保存しないため、ほかのページは印だけです）。「表示:」で理由を1つに絞り、
  「ページ」や「理由」の見出しをクリックすると並べ替えます。選ぶとそのページが何ページ目かを伝えます。ビューアには何も送らないので、
  そのページへはご自分でめくり、そこで「レビュー...」から直してください。一覧は、ページを訳すたび、変更するたびに新しくなります。
* 「レビュー...」は、そのページで見ておくべき領域（要確認の印、未訳、読者への訳注あり）を一覧にします。
  自動の写植がうまく収まらなかった領域も載ります: 文字が吹き出しの縁に触れている、文字が吹き出しの中央からずれている
  （つながった2つの吹き出しの訳を片方に置いたときなど）、単語がハイフンで分割されている、短い単語が1語だけの行がある、
  前後の行よりずっと短い行がある、文字が背景に対して見えにくい。
  編集画面の「もう一度訳す」は前の台詞を文脈にしてその吹き出しを訳し直させます（別案を並べる機能はありません）。
  その訳でも、シリーズ設定と違う綴りの名前や用語を機械的にそろえます。
  前の同じセリフから使い回した訳は、編集画面がそう伝えます（「短いセリフの使い回し」）。「もう一度訳す」で新しい訳が出ます。
  辞書にない語を含む訳文も要確認にするには、設定のスペルチェック（設定ファイルの `spellcheck = true`。既定でオフ）を使います。
  その単語リストは任意の追加分で、TASlation はインストールしません。Python パッケージ `pyspellchecker`（MIT ライセンス。英語・スペイン語・フランス語・ポルトガル語・ドイツ語・イタリア語・ロシア語・オランダ語の単語リストをディスクに持ちます）で、
  これが TASlation の Python に追加されているときだけチェックが働きます。シリーズ設定の名前と表記は対象外です。
  設定がオンなのに単語リストが入っていないときは、編集画面を最初に開いたときに一度だけそう伝え、設定をオフにする場所
  （「設定...」の「設定ファイルを開く」）も示します。ネットからは何も取得しません。
* 「元に戻す」は表示中のページの変更（訳文や注記の編集、領域の移動・大きさの変更・追加・削除（複数の領域をまとめて
  した変更も1回）、保存した書式、種別と文字サイズの設定、
  「このページを除外」、読み順の設定、訳し直し）を新しい順に取り消し、
  「やり直す」でまた適用します。ほかのページでの変更は、そのページを再び表示したときに取り消せます。
  訳し直しを取り消すと、そのページの前の訳文が戻ります。何も訳さずに終わった訳し直し（停止など）は取り消す対象になりません。
* 「検索と置換...」は、今の本の、今の言語の訳文全体を検索して置き換えます
  （「対象:」で選べば、そのシリーズのほかの巻でも置き換えます）。
  たとえば人物名の誤りを1冊分まとめて直すときに使います。ダイアログを開いたまま本を読み進められ、入力するたびに、一致した箇所が
  ページ番号と前後の文字とともに一覧に出ます（`«` と `»` の間が一致した部分です。ページ番号は本のノンブルではなく、
  キャッシュに入った順の番号です）。「大文字と小文字を区別」と「単語全体」で絞り込めます。「単語全体」は、日本語、中国語、韓国語、
  タイ語のように単語の間に空白を置かない文字の隣では区切りを見ません。
  「置換」のボタンを押すまで何も書き込みません。「選択した行を置換」は一覧で選んだ箇所だけを（Ctrl キーと Shift キーで複数選べます）、
  「すべて置換」は一致したすべてを置き換えます（一覧に出るのは最初の500件までですが、件数と「すべて置換」は全件が対象です）。
  表示中のページはすぐに写植し直し、ほかのページは次に表示したときに新しい訳文で出ます。

  変わるのは訳文だけです。要確認の印、読者への訳注、下訳の印、未完了のページの印、吹き出しの位置はそのまま残ります。
  訳文の大きくする部分は言葉と一緒に動き、置換がその部分に触れたときは、その吹き出しを一つの大きさで写植します。
  1行ずつ見て直したわけではないので、領域の編集と違って、要確認の印を消しません。訳文が空になってしまう吹き出しは置き換えず、そう表示します。
  置換は全体で1回の変更で、それが本の最新の変更である間は、どのページを表示していても「元に戻す」で全ページまとめて元に戻せ、
  「やり直す」でまた適用できます（検索と置換のダイアログの中では、Ctrl+Z と Ctrl+Y でも同じです）。そのあとにほかのページを編集すると、先にその編集を取り消す必要があります。
  訳し直されて内容が変わった吹き出しは、元に戻す対象から外れます。

  シリーズ設定は自動では変わりません。「すべて置換」で置き換えた語句がシリーズ設定の表記だったときだけ、領域の編集のときと同じように、
  新しい表記にするかを1回だけ尋ねます。一部の行だけを置き換えたときは尋ねません。元に戻してもシリーズ設定の変更は戻りません。
  ページの処理中は置き換えられません。終わってからもう一度押してください。

  「対象:」は「すべて置換」で置き換える範囲です。「この本」（ダイアログを開くたびにこちらから始まります）か「シリーズの全巻」を選びます。
  「シリーズの全巻」でも一覧はこの本だけを表示し、「すべて置換」は先に、同じ言語で保存されているこの本のシリーズのほかの巻
  （`taslation glossary apply` と同じく、シリーズ名で見つけます）の一致を数えて巻ごとに示し、確認します。
  「全巻で置換」は、この本では「すべて置換」と同じように置き換え（「元に戻す」で元に戻せます）、ほかの巻ではそれぞれ置き換えてすぐに保存します。
  ほかの巻には「元に戻す」が届きません。巻を変える前に、変更前のファイルのコピーをその隣に残します（`<file>.before-replace.<date>.json`。キャッシュと同じく保護されます）。
  元に戻すには、全巻を対象に逆向きに置換するか、そのコピーを元のファイルの代わりに戻してください。ほかの巻で置き換えた行も、自分の修正として印が付きます。
  「選択した行を置換」は常にこの本だけが対象です。
* 「この本の設定...」は、この本に合う検出と OCR の値（しきい値、文字ブロックの検出、効果音）と、この本の写植の大きさ
  （「写植の大きさ」と「最大の大きさ」。「設定のまま」と空欄は「設定...」の値）を、自分の設定を変えずに、
  本の前提情報と一緒に保存します。「この本に適用」を押すと、表示中のページをキャッシュから組み直します（訳し直しはしません）。
  「読む方向」は、見開きのどちらのページとどの吹き出しを先に読むかです（既定は「右から左（日本の本）」、ほかに「左から右」）。
  「すべて消去」ではこの設定は変わりません。
  「すべて消去」は、消える設定の数を示して確認してから消し（既定のボタンは「残す」です）、
  ダイアログを開いたままにします。その間は「元に戻す」で消した設定を戻せます。その下には、この本の全ページで無視する範囲が
  当てはまるページ（全ページ・右側のページ・左側のページ）と位置（ページの幅と高さに対する %）で並び、「範囲を削除」（一覧で Delete キーでも可）で
  選んだ範囲をすぐに外せます（そこでも再び文字を探します）。「元に戻す」は、このダイアログで最後にしたこと（すべて消去か範囲の削除）を取り消します。

  同じシリーズの巻どうしで、これらの値を共有できます。「シリーズの既定値として保存」は、表示中の値をこの本に適用し、その値（選択、大きさ、ほかの設定、読む方向）をシリーズの既定値として保存します。
  範囲の横の「この範囲をシリーズに使う」（メニューの「ページ」にもあり、本にシリーズがないときは灰色）は、一覧の範囲をシリーズの範囲として保存します。初めて開いた巻（自分の値がまだ何も保存されていない巻）はシリーズの既定値から始まり、自分の値がないところでは既定値に従い続けます。
  そうした値には「（シリーズの既定値）」「シリーズの既定値（...）」「（シリーズの既定値: ...）」と表示され、その巻で決めた値が常に優先されます。「すべて消去」はシリーズの既定値（シリーズに値がないところは自分の設定）に戻します。
  範囲は、その巻で外したり加えたりするまではシリーズの一覧をまるごと使い、その後はその巻だけの一覧になります。シリーズは、巻数のある本の「シリーズ」欄です（大文字と小文字、空白の違いは区別しません）。
  巻数のない本にはシリーズの既定値はなく、以前から注釈が保存されている本は、これまでどおり自分の値だけを使います。範囲はページとその形に対する位置で保存されるので、別の大きさで取り込んだ巻にもそのまま合い、
  ページの形が違う巻には使われません。シリーズの既定値は `~/.taslation/annotations/series/` に、注釈と同じく保護して保存します。
* 「シリーズ設定...」は、シリーズごとに、用語（用語とその訳語・表記）、登場人物（性別、年齢、一人称、話し方、役割、ほかの人物の呼び方）、
  文体ガイド（敬称の方針、トーン、ハウスルール、シリーズが提案する描画フォント、種別ごとの書体と文字の色・縁取り・縁取りの色）を保存します。種別ごとの色と縁取りは、その種別の領域の「自動」になり、編集画面で領域ごとに決めた色と縁取りがそれより優先されます。書体以外はすべて、
  翻訳の前にモデルに伝えます。入れるのは事実だけで、本の台詞は入れません。描画フォントは Comic
  Neue のようなファミリー名で指定し（`taslation glossary font` でも設定できます。描画フォントと種別ごとの書体の欄は一覧からも選べ、
  編集画面と同じく、スターを付けたフォントと最近使ったフォントが先頭に並び、横の ☆ でスターを付けられます）、
  そのフォントがこのパソコンに入っていれば字形がある限り使い、入っていなければそう表示して、自動選択のフォントを使います。
  用語や登場人物の「選択項目を削除」は、削除するものの数と名前を示して確認します（既定のボタンは「残す」です）。
  下の「元に戻す」は、このダイアログで最後に加えた変更（追加・更新・削除・文体ガイドの保存）を1回分取り消します。
  用語や登場人物の訳語・表記を変えると（「元に戻す」で戻したときも）、古い表記を使っている翻訳済みの行がいくつあるかを示し、
  新しい表記にするかを尋ねます。「{n} 行に適用」で、キャッシュのその本・その言語の訳文を単語単位で置き換えます（「Miyu」を変えても
  「Miyuki」は変わりません。表示中のページはすぐに写植し直します）。置き換えは全体で1回の変更で、検索と置換と同じく、メニューの「元に戻す」で元に戻せます。
  ページを処理中なら終わってから尋ねます。
  同じ言語で保存されているシリーズのほかの巻にも古い表記があるときは、質問にその巻と行数が並び、「シリーズの全巻」のチェック
  （最初は外れています）を入れると、それらも新しい表記にします。古い表記がほかの巻にしかないときは、それらの巻についてだけ尋ねます。
  ほかの巻はすぐに保存され、「元に戻す」は届きません。それぞれのファイルの変更前のコピーをその隣に残します（`<file>.before-replace.<date>.json`）。
  元に戻すには、表記を元に戻して全巻に適用するか、そのコピーを戻してください。これらの行は、この本でもほかの巻でも、自分の修正としての印は付きません。

話者、種別、続きの印、注記はそれぞれの吹き出しに添え、シリーズ設定は吹き出しの前に置いてモデルに渡します。保存先は
`~/.taslation/annotations/<book>.json` と
`~/.taslation/glossary/<series>.json`（同じファイル名になる名前は `<name>-<hash>.json`）で、
中身は位置、事実、方針だけです。本文も訳文も入りません。どちらも訳文のキャッシュと同じように保護して保存します（「訳文のキャッシュとバックアップ」）。

前提情報の効果は、本がなくても
`python tools/premises_eval.py` で測れます（テスト用の台詞をシリーズ設定ありとなしで訳し、名前、代名詞、敬称、
分かれた文、話し方を採点します）。既定のモデルでは、シリーズ設定で通過率が58%から90%に上がりました。実際の巻を、
本と照らして事実を確かめたシリーズ設定で訳し直すと、人物名の誤りは208件から0件になり、文脈付きのブラインド評価では、
変わった吹き出しの51%で新しい訳が、36%で古い訳が好まれました（`docs/OFFLINE_VERIFICATION.md`）。
事実は先に確かめてください。モデル自身の推測で書いたシリーズ設定は、ないのと変わりませんでした。

### ページ指紋

ページ指紋は、ページの内容部分の320ビットの知覚ハッシュ（縮小したページの 16x16 の勾配ハッシュと 8x8 の明るさのハッシュ）で、
ファイルのハッシュではありません。同じページを別の大きさやズームで取り込んでもほぼ同じビットになり、違いが36ビット以内なら「同じページ」とみなします。
ウィンドウの大きさが変わると、内容部分そのものが違って取れることがあります（縁が黒い絵のページを、横にビューアの背景をわずかに含めて読んだとき。ページの端にある1ピクセルほどの線。見開きが入らない狭いウィンドウで、ページが1枚ずつ表示されたとき）。
そのため、いま読んだままではキャッシュにないページは、別の大きさで読んだときの取り方でも、同じ36ビット以内で探します。ある大きさで翻訳したページは、別の大きさでもモデルに聞き直さずにキャッシュから表示されます。
指紋からページを復元することはできません。似たページ（白紙、繰り返し出る広告）は、縦横比と順序の中の位置で区別します。

### ブラウザで読む場合: 本のタブを専用のウィンドウに

ブラウザのウィンドウはタイトルで見分けますが、ブラウザのウィンドウのタイトルはアクティブなタブのものです。
本のタブがほかのタブと同じウィンドウにあると、TASlation はそのタブが前面にある間しか本を見られません。

対策は一度だけで済みます。リーダーのタブをウィンドウの外へドラッグして（またはタブを右クリックして「タブを新しいウィンドウに移動」）、
専用のウィンドウにしてください。そのウィンドウはほかの作業の後ろに開いたままにしておきます。隠れていてもかまいませんが、最小化はしないでください。
デスクトップのビューアは独立したアプリなので、この対策は要りません。画像ビューアなどブラウザ以外のウィンドウは、ページをめくるたびにタイトル（ファイル名やページ番号）が
変わっても、同じウィンドウが開いている限り本として扱い、タイトルの変化では待ちません。ウィンドウが非表示か最小化されたときだけ、
ステータス行にそう表示して元に戻るのを待ちます。

それでもウィンドウが別のタブを表示していた場合、自動はタイトルの変化に気づき、ステータス行にそう表示して、本が戻るのを待ちます。
違うページを読むことはありません。

読み取りが巻末に達すると、ビューアによっては巻末のパネル（評価、次の巻）を表示します。矢印キーではこのパネルから出られないことがあるので、
そのときは「x」で閉じてから1ページ目に戻ってください。ビューア自身の部品や奥付のページのように見える文字（ラテン文字や数字の並んだ横書きの行：
価格、アドレス、評価、発行日、各話の初出の記録）は、台詞ではなく印刷物とみなして、そのままにします。扉のページの作品名と作者名もそのままです。
章の見出しや目次の言葉（第3話、第十二章、最終話、番外編、目次、あとがきなど）は、横書きでも、帯の上でも、ページ番号の隣でも訳し、目次は1行ずつ訳します。
数字やラテン文字と並んだ日本語も、確かに読めたものは訳します（3年B組、ラテン文字の副題がある見出し）。ラテン文字だけで別の行にある副題は、そのままです。
横書きの段落（解説のページ、まえがき）は、切れ切れにせず、段落ごとに読んで書き入れます。

### 訳文のキャッシュとバックアップ

キャッシュは `~/.taslation/cache/<book>.json` にあり、
翻訳先の言語ごとに1ファイルです（書名はビューアのウィンドウのタイトルからとり、「メニュー > シリーズと巻...」で変えられます。"My:Book 1" と "My
Book 1" のように同じファイル名になる本は `<book>-<hash>.json`）。「メニュー > 保存した翻訳...」で、
キャッシュを一覧・削除できます（一覧では本をシリーズと巻に分け、ページ数、吹き出し数、ファイルのサイズ、言語、最終更新を示し、
その下にファイル数・ページ数・容量の合計を出します）。見出しをクリックするとその列で並べ替え、もう一度クリックすると逆順になります。
最初はシリーズ、巻、言語の順です。Ctrl+クリックと Shift+クリックで複数の行を、Ctrl+A ですべての行を選べます。「削除」は選んだ行の本の、それぞれその行の言語のファイルだけを Windows のごみ箱に移します
（ほかの言語の訳文は残ります）。確認は1回だけで、本の名前か、件数とその本を示します。確認の既定のボタンは「残す」で、ごみ箱から元に戻せます。ごみ箱に移せないファイル
（ごみ箱のないドライブなど）は削除せず、そう表示します。コマンドラインの `taslation cache delete` は従来どおり全言語を削除します。
「書名を変更...」は、選んだ1冊に「シリーズ」と「巻」の欄で新しい書名を付けます。変更はほかの書名変更と同じように進み（シリーズ設定の内容が違うところがあれば先に確認します）、
すべての言語の訳文、ページ情報、シリーズ設定も一緒に移り、終わると一覧に反映されます。ファイルに入っているのは訳文、正規化した吹き出しの形と位置、ページ指紋、読者への訳注（大きくする部分がある吹き出しでは、その部分の訳文の中の位置も入ります）、
奥付にある本の書誌（書名、巻、著者、発行所、ISBN）、使い回すために残す短いセリフの訳文です。短いセリフは日本語の鍵付きハッシュで引き、日本語そのものは入りません（「短いセリフの使い回し」）。ページ画像は入りません。
TASlation が保存するものはすべて「メニュー > ヘルプ > 使い方...」の「データについて」に挙げています。
モデルが物語についてのノートを書いて残すことはありません（古い版が
`~/.taslation/series` に書いたノートのファイルは、読まずにそのまま残ります。要らなければ削除してかまいません）。

キャッシュ、ページ情報、シリーズ設定のファイルは（横に残した控えや、古い版のノートのファイルも）、Windows の機能（DPAPI）で保護して保存し、
このパソコンのあなたの Windows ユーザーしか開けません。パスフレーズはありません。別のパソコンにコピーしても、別の Windows ユーザーが開いても読めません。
ただし、あなたの Windows ユーザーで動くプログラムなら、TASlation と同じように開けます。ファイル名は `.json` のままですが、中身はもう JSON ではないので、
テキストエディタで開いても訳文は読めません。中身は `taslation cache list`、`taslation review`、`taslation glossary show` で確かめてください。
以前のバージョンが保存したファイルは、起動したときに1つずつ保護した形に置き換えます（ステータス行とログには件数だけを出します）。
ほかのプログラムが使っていて置き換えられなかったファイルはそのまま読み、次の起動でまた試します。`taslation cache protect` でも置き換えられ、
`taslation audit` は保護されていないファイルが残っているかを表示します。保護したファイルは、この版より前の TASlation では読めません（読めないファイルとして横に残します）。
以前のバージョンが保護せずに保存したファイルや、削除したファイルの中身は、ディスクに復元できる形で残っていることがあります。

TASlation が読めないキャッシュ、ページ情報、シリーズ設定のファイル（壊れているもの、新しいバージョンで書かれたもの、別の Windows ユーザーや別のパソコンで保存されたもの）は上書きしません。
`<name>.unreadable-<date>.json` として横に残し、コンソールに1行出して、新しいファイルに置き換えます。
このパソコンで開けないファイルがあると、TASlation は起動したときにその件数と訳文の移し方を表示します（件数が変わったときだけ）。
本やシリーズを削除すると、こうした控えも削除されます。

本のキャッシュは、パスフレーズで暗号化したファイルにして、自分用の控えにしたり自分の別のパソコンに移したりできます（「保存した翻訳...」、
または `taslation cache export` と `taslation cache import`）。ファイルには訳文と、その本のページ情報
（追加した枠や飛ばした枠、話者と訳注、本ごとの設定、ページの順序）と、その本がその言語で使うシリーズ設定と、シリーズの既定値（ファイルの中では同じシリーズの巻すべてで1つ）が入っているので、
自分だけで持っていてください。パスフレーズがなければ TASlation を含め誰も開けず、忘れたパスフレーズは取り戻せません。
1つのファイルに複数の本を入れられます。「保存した翻訳...」では選んだ行すべて、コマンドラインではシリーズまるごと（`--series NAME`。そのシリーズの、翻訳先の言語でキャッシュのある巻すべて）か、すべての本（`--all`）です。
ページの画像やページから読み取ったセリフは入らず、入るのは保存したファイル自体にあるものだけです。
保存したファイルをそのままコピーしても別のパソコンでは読めないので、訳文、ページ情報、シリーズ設定、シリーズの既定値を移せるのはこの方法だけです。
管理者が Windows のパスワードをリセットしたとき（自分でパスワードを変えたときは問題ありません）、新しい Windows のプロファイルにしたとき、
Windows を入れ直したときは、保護したファイルを開けなくなります。訳文が大切なら、書き出したファイルを取っておいてください。
前のバージョンで書き出したファイル（1冊の訳文）も取り込めます。この版で書き出したファイルは前のバージョンでは取り込めず、
新しいバージョンのファイルだと伝えて何も取り込みません。取り込んだファイルも保護して保存します。

* 書き出しと取り込みは、それぞれ警告から始まります。書き出したファイルはあなた専用で（本が自分のものでも、他人に渡せば著作者の権利の侵害になります）、
  取り込むのは自分のパソコンで自分が作ったファイルだけです。そこで「キャンセル」を押せば、ファイルを選ぶ前に止まります。
* パスフレーズは入力中に足りないものを表示し、「表示する」で伏せ字を外せます。全角スペースは半角スペースとして扱います。
  追加パッケージ `cryptography` がなければ、書き出しと取り込みは灰色になります。
* すでに訳文のある本への取り込みは、既定では統合します。ファイルのページは追加されるか、こちらのページと入れ替わりますが、
  ここで直した訳は、その吹き出しのファイル側の訳がモデルのものである（またはファイルに訳がない）限り残ります。
  ファイルをそのまま採るとき（`--take-file`。`--replace` はキャッシュ全体を置き換えます）は除きます。書き込む前に、
  追加・入れ替えるページの数と、残すあなたの修正の数を伝えます。
* ここにすでにあるページ情報は、ファイルのものを採ると選ばない限り残ります。ここにすでにあるシリーズの既定値も同じです。ここにすでにあるシリーズ設定は、名前の変更で
  2つのシリーズ設定を合わせるのと同じようにファイルのものと合わせます。ファイルが加えるものは加え、両方で違うところはファイルのものを採ると選ばない限りあなたのものが残ります。
* 「保存した翻訳...」では、複数の本が入ったファイルや、あなた自身の修正、ページ情報、シリーズの既定値、シリーズ設定の値にかかわるファイルを取り込むとき、
  先にファイルの中身と取り込みの結果を示し、「取り込む」を押すまで何も書きません。取り込む本、「自分の修正を残す」（既定）か「ファイルのとおりにする」か、
  ページ情報とシリーズの既定値はそれぞれ「自分のものを残す」か「ファイルのものにする」か、シリーズ設定は違うところごとに選べます。
* `cache import FILE --list` は何も取り込まずにファイルに入っている本を一覧し、`--book NAME`（複数ならくり返す）はその本だけを取り込みます。
* 取り込みのたびに、変更するファイル（キャッシュ、ページ情報、シリーズ設定、シリーズの既定値）をどれも `<name>.before-import.<date>.json` として横に残すので、
  手作業で戻せます。パスフレーズが違う、ファイルが壊れている、大きすぎる（本のキャッシュが5,000ページ超、
  または1ページに500吹き出し超。1つのファイルに1,000冊超か100,000ページ超）、新しいバージョンの TASlation で作られた部分を含む場合は、何も書かずに拒みます。
  1つのファイルから読み戻せないほど大きな書き出しも拒みます。一度に書き出す本を減らしてください。
* `cache export` は、`--force` を付けない限り既存のファイルを上書きしません。

`cache export` と `cache import` は、パスフレーズの前に標準エラー出力へファイルの用途の説明を出すだけで、
それ以上は尋ねないので、スクリプトから無人で実行できます。`--confirm` を付けると「Continue? [y/N]」と尋ね、
yes 以外では何も読み書きせずに終了ステータス1で終わります。あなた自身の修正、ページ情報、シリーズの既定値、シリーズ設定の値にかかわる取り込みは、
それらをどうするかを標準エラー出力に出し、`--confirm` があればもう一度尋ねます。パスフレーズは表示せずに尋ねます。環境変数
`TASLATION_PASSPHRASE` はスクリプト専用です。PowerShell の PSReadLine は
`$env:TASLATION_PASSPHRASE = "…"` のような行を履歴ファイルに書き込むためです（秘密情報のフィルターは
"password" には反応しても "passphrase" には反応しません）。安全なのはコマンドのプロンプトで入力することです。
それでも変数を使うなら、値をコマンドラインに書かず、シェルに尋ねさせてください:

```
$env:TASLATION_PASSPHRASE = Read-Host -MaskInput               # PowerShell 7
read -rs TASLATION_PASSPHRASE && export TASLATION_PASSPHRASE   # bash, zsh
```

### 短いセリフの使い回し

同じ本、または同じシリーズのほかの巻ですでに訳した短いセリフがまた出てきたときは、モデルに尋ねずに同じ訳を使います（設定
`reuse_lines`、既定でオン。「設定...」の「前に出た短いセリフの訳を使い回す」）。同じ叫びや返事、呼びかけはページを
またいで何度も出てきます。訳を使い回せば問い合わせが1回省け、毎回同じ訳になります。対象は10文字までのセリフです（読みの
変わらない違いはそろえてから比べます。全角と半角、空白、「……」と「...」、「〜」と「ー」、「!?」と「！？！」、末尾の「。」）。
次の吹き出しへ文が続くセリフ、前の吹き出しから続くセリフ、モデルへのヒントを付けたセリフは、いつも訳させます。領域の編集画面で
付けた話者と種別もセリフの一部です。同じ言葉でも別の人のセリフや、心の声にしたセリフは、別のセリフとして扱います。使い回すのは
同じモデルで同じ言語へ訳したものだけで、別のシリーズの訳は使いません。シリーズは、シリーズ設定と同じく「シリーズ」欄で決まります。
2つの欄ができる前に入力した名前のままの巻（「Some Title 3巻」）も、「Some Title 4」とセリフを共有します。

* 自分で直した訳が優先されます。後から出てくる同じセリフには、直した訳が入ります。編集画面の「もう一度訳す」はモデルに
  尋ね、その答えを保存すると、ここではあなたの修正として扱います（「自分の修正」には入りません）。前の同じセリフから使い回した訳のときは、
  編集画面がそう伝えます。修正を「元に戻す」で取り消すと、使い回し用に残した訳も元に戻ります。
* ページの訳し直し（丸い矢印）では、自分で直したセリフ以外をすべてモデルに尋ね（直したものも置き換えると指定した場合を除く）、
  モデルの前の訳を新しい答えで置き換えます（あなたの修正は置き換えません）。
* 残すのは、ページに出したとおりの、シリーズ設定の綴りにそろえた訳です。残した訳は、使う前に今のシリーズ設定と照らし合わせます。
  名前の綴りが違えば訳したばかりの訳と同じように直し、シリーズ設定の表記がまだ足りない訳は使いません（モデルに尋ねます）。
* OpenMantra の5つの短い作品では、この決まりで使い回すセリフは、全ページを一度に通して訳したときにセリフの 3.5 %、翻訳の時間の
  約 3.5 % でした（1ページずつでは 4.0 % と 3.8 %）。そのセリフをモデルに訳し直させても、使い回した訳よりプロの訳に
  近いと言える差は出ず、同じページのほかのセリフの訳も、使い回しなしのときと変わりませんでした
  （`docs/OFFLINE_VERIFICATION.md` の「Line reuse」）。長い本ほど繰り返しは増えます。
  使い回しの弱みは、最初の訳が外れていると、同じセリフが出るたびにその訳が出ることです。一度直せば（またはページを訳し直せば）、
  その後はすべてに届きます。

残すもの: 本のキャッシュのファイルに、そうしたセリフごとの鍵付きハッシュ（その本だけのランダムな鍵による HMAC-SHA-256。鍵は
同じファイルに入ります）とその訳。日本語は書きません。ファイルのほかの部分と同じく保護され、`taslation cache list` に数が出て
（「line(s) kept for reuse」）、本の訳文と一緒に削除され、暗号化したエクスポートに入り、インポートで戻ります（自分のセリフを
持つキャッシュへのインポートは、足りないセリフだけを加えます）。鍵がファイルの中にあるので、ファイルを開ける人（あなたの
Windows ユーザー、またはエクスポートとそのパスフレーズを持つ人）は、思い当たるセリフがその本にあったかどうかを確かめられます。
短い感嘆の言葉は当てやすいものです。設定をオフにすると、それ以後は使い回しも保存もしません。それまでに残したものは、本の訳文を
削除するまでキャッシュに残ります。このセッションで使い回したセリフの数は、「設定」の「システム」ページに出ます。

### ほかの言語への翻訳

翻訳先の言語は左のペインの言語の行（または `--language`、設定の `target_language`）で選びます。
キャッシュとシリーズ設定は言語ごとに保存され、写植はその文字体系のフォントに切り替わります。訳すモデルは翻訳先の言語で決まります
（「モデルの選び方」）。品質はその言語でのモデルの力によります。訳の質を測ったのは英語への翻訳だけで（「モデルの選び方」）、
いま使うモデルは、ほかの翻訳先の言語では測っていません。
ヒンディー語とベンガル語は HarfBuzz（install.cmd が入れる `uharfbuzz` パッケージ）で字形を整形し、結合文字・母音記号・
レフ（上に付く r）をフォントのとおりに組みます。このパッケージがない PC では文字が1つずつ描かれ、右のペインにそのことが
表示されます（install.cmd をもう一度実行してください）。それ以外も、右から左に書くアラビア語とヘブライ語を含め、正しく組まれます。
ただしヘブライ語の母音記号（訳文にはまず現れません）は、隣の文字に付いてしまうことがあります。

### モデルの選び方

既定（`ollama_model = "auto"`）では、翻訳先の言語がモデルを決めます。

| 翻訳先 | モデル（Ollama 名） | ダウンロード | ライセンス | 訳し方 |
|---|---|---|---|---|
| ブラジルポルトガル語とトルコ語以外のすべて | PLaMo 3 Translate 2B（Preferred Networks。`taslation-plamo3-translate-2b`、Q4_K_M） | 1.8 GB | PLaMo Community License | 1行ずつ |
| ブラジルポルトガル語、トルコ語 | Qwen3.5 4B（`qwen3.5:4b`） | 3.3 GB | Apache-2.0 | 約30行ずつ |

PLaMo 3 Translate は翻訳専用のモデルです。TASlation はその PFML3 形式のプロンプトを自分で組み、Ollama の `/api/generate` に
そのまま送ります（モデルカードが本番の利用に勧める形です。モデル自身のチャットテンプレートは使いません。以前の版のファイルのテンプレートには Ollama から
翻訳先を指定できず、日本語に戻してしまいました。今の版のファイルのテンプレートは、TASlation と同じプロンプトを組みます）。1行ごとに1回の要求で、
前の台詞とその訳、参考情報としてシリーズ設定（話者を指定した行はその話者も）、その行に出てくるシリーズ設定の訳語を用語集として渡します。
前の台詞はページごとに増やしていき、60 を超えたときだけ新しいほうの 20 に切り詰めます。こうすると各要求のプロンプトが前の要求のプロンプトの続きになり、Ollama はその部分を計算し直しません
（ページごとに1ページ分ずらしていたときは、各ページの最初の要求に 142 ms ではなく約 1,050 ms かかっていました）。
領域の「モデルへのヒント」は、その行だけの参考情報に入れます。作った台詞で試したところ、ヒントに従ったのは 78 回中 38 回（ヒントなしで 17 回）で、悪くした訳はありませんでしたが、
言葉づかいや誰に向けた言葉かには一度も従わず、何も変えないはずのヒントで 30 回中 5 回は言い回しが変わりました（docs/OFFLINE_VERIFICATION.md）。領域の編集画面にもそう表示します。
コンテキストは 8192 トークン、GPU のメモリは約 1.9 GB です。OpenMantra（日本語から英語、1冊まるごと、シード固定で3回ずつ）では、
Qwen3.5 4B より chrF が 5.9 高く（ブートストラップの区間でおよそ +4.7〜+7.2）、速さは約2倍でした。
ブラジルポルトガル語とトルコ語は書けない（別の言語で答える）ので、この2つだけ Qwen3.5 4B が JSON のチャット形式で訳します。

入れておくのは翻訳先に要るほうの1つだけで済みます。install.cmd は最初の質問で翻訳先の言語を尋ね、その言語のモデルを取得します。
一覧の番号か英語の名前で答えます（一覧にない言語も、PLaMo か Qwen が書ける言語なら名前で選べます）。Enter なら、
TASlation で最後に選んだ言語、なければこの PC の表示言語に合う言語、なければ英語です。`taslation.toml` に `target_language` があれば、
尋ねずにそれを使います。表示されたものと違う言語を選ぶと、TASlation もその言語で始まります（`ui.json` に書きます）。
install.cmd の質問は、Windows の表示言語が日本語なら日本語で表示します（訳文は `installer-texts.json` にあり、ほかの言語も足せます。
訳のない言語では英語です）。
左のペインで別のモデルが要る言語を選ぶと、TASlation がそのモデルのダウンロード（大きさを表示）と、要らなくなったほうの削除を提案します。
TASlation が入れる翻訳モデルは一度に1つだけです。TASlation が入れたのではないモデル（もともとあなたが入れていた `qwen3.5:4b` など）は、
消すかどうかを別に尋ね、既定では残します。PLaMo を初めて入れるときは、先にそのライセンス（2026年11月9日改定の PLaMo Community License。
要点は `docs/THIRD_PARTY.md`）への同意を尋ねます。改定前の文面に同意して入れた PLaMo は、そのまま使えます。改定後の文面への同意は、次に PLaMo を入れるときに尋ねます。
配布元のサーバーがダウンロードを拒否したか、ファイルをもう置いていないときは、もう一度試しても変わらないので、TASlation を更新するか、プロジェクトの Issues ページを見るよう表示します。
コマンドでは `--language` で同じことを尋ね、`python setup_models.py --translator-for "Turkish"` でも入れられます。
`ollama_model` に自分のモデル名を書いているときは、何も提案しません。
PLaMo が入っておらず Qwen があるときは、そのあいだ Qwen で訳し、右のペインにそう表示します。
翻訳先に要るモデルが入っておらず代わりもないときは、右のペインにそのモデルが入っていないことを表示します。どちらの場合も、メニューの
「モデルをダウンロード」で、install.cmd を実行し直さずにその場で入れられます。
`ollama_model` にほかのモデル名を書けば、そのモデルをチャット形式のプロンプトで使います（以下はそうした選び方の記録です）。

どちらのモデルも訳すだけです。巻の翻訳ノートを書く、訳を見直す、長すぎる訳を短くする、別案を出すといった、
モデルへの追加の要求はしません（2026-11-06 に廃止）。日本語をそのまま返した行や抜けた行だけは、自動で訊き直します。

以下は、2026年11月まで既定だった Qwen3.5 4B を選んだときの記録です。

文字は OCR モデルが読むので、言語モデルが見るのは文字です。言語モデルに画素は一切送りません。テキスト専用のモデルでもかまいません。画像対応のモデル（Gemma 4、
Qwen 3.5/3.6、Ministral 3）の視覚部分の重みは、4B では負担が小さく、9B 以上では大きくなります。モデルに必要なのは、
翻訳の質に加えて、長いコンテキスト、幅広い言語への対応、用語集に従う力です。

候補は、日本語から英語への翻訳を専門に採点する唯一の公開ベンチマーク
[JP-TL-Bench](https://github.com/shisa-ai/jp-tl-bench)（LLM による一対比較、
0〜10の「LT」スコア。数値は [論文](https://arxiv.org/abs/2601.00223) の JA→EN 方向）から、
普通のパソコンで動くテキスト専用の公開モデルを選びました。

| モデル（Ollama 名） | JA→EN LT | ダウンロード | コンテキスト | ライセンス |
|---|---|---|---|---|
| `qwen3:30b-a3b-instruct-2507-q4_K_M`（最高品質） | 9.77 | 19 GB | 256K | Apache-2.0 |
| `hf.co/XpressAI/shisa-v2.1-unphi4-14b-GGUF:Q4_K_M` | 9.36 | ~9 GB | 16K | MIT |
| `hf.co/XpressAI/shisa-v2.1-qwen3-8b-GGUF:Q4_K_M` | 9.02 | ~5 GB | 40K | Apache-2.0 |
| `qwen3:8b` | 7.94 | 5.2 GB | 40K | Apache-2.0 |
| `qwen3:4b-instruct-2507-q4_K_M` | 記載なし（4B のベース: 5.34） | 2.5 GB | 256K | Apache-2.0 |
| **`qwen3.5:4b`**（ブラジルポルトガル語とトルコ語の既定） | 記載なし | 3.3 GB | 256K | Apache-2.0 |

`qwen3.5:4b` は、実際の巻を使った 4B
クラスのモデルの勝ち抜き戦で勝ちました（`docs/OFFLINE_VERIFICATION.md` の「Lighter models compared」と「A knockout among the 4B models」）。
以前のバージョンの1冊まるごと読む機能と同じ方法で訳すと、その訳は Qwen3 4B の最良のビルドと同じくらい 30B の訳に近く（401行で chrF 45.7。
Qwen3 4B は Q6_K で 46.2、Q4_K_M で 44.5）、シリーズ設定にも同じくらいよく従い（45のチェック中39。30B は41）、
その中で最も速いモデルです。Ollama の KV キャッシュを量子化すれば（「インストール」参照）、6 GB の
GPU で 16K のコンテキストを保ったまま毎秒60トークンで生成し、同じマシンの 30B の約4倍の速さです。視覚部分の重みは使わず、
思考モードは要求ごとにオフにしています。30B を判定役にしたブラインド評価では、
Qwen3 4B は 30B をわずかに下回りました（162行のうち 30B の訳が89行、Qwen3 4B の訳が63行で好まれました）。

最高の品質を求めるなら `qwen3:30b-a3b-instruct-2507-q4_K_M` です。アクティブなパラメータが 3B の MoE で、
約 20 GB の RAM が必要ですが、GPU のメモリはあまり使いません。開発に使ったマシンでは、短いコンテキストで毎秒17トークン、
32K のコンテキストで毎秒11トークンで生成します。RAM に余裕があれば取得して、`ollama_model` と
`ollama_num_ctx = 32768` を設定してください。ほかの候補は次のとおりでした。

* Shisa V2.1 8B（日英向けの調整で、ほかの翻訳先は想定外）は品質では 30B に並びますが、密なモデルなので、
  実用的なコンテキストでは 6 GB のカードに収まりません。
* Hy-MT2（`kaelri/hy-mt2`。翻訳専用）は 1.8B でさらに速いものの明らかに劣り、
  7B は長い要求で吹き出しを混ぜてしまいます。
* TranslateGemma 4B は構造化した要求に従いません（40回の要求で、まともな訳は1回）。
* Index-Translate（`hf.co/IndexTeam/Index-Translate-2B-GGUF:Q4_K_M` と 9B）も負けました。2B は8行に1行を訳さずに残し、
  9B は 6 GB のカードに収まらず5倍遅いうえ、30B に近づきません。
* JP-TL-Bench でこれより高いのは `ministral-3:14b`（9.88）だけですが、視覚部分の重みを含み、
  快適に使うには 12 GB の GPU が必要です。Gemma 4、Qwen 3.5、TranslateGemma は
  JP-TL-Bench に載っていません。日本語の総合リーダーボード Nejumi 4 では、Qwen3.5-9B（0.749）が Gemma 4
  E4B（0.669）を大きく上回っています。

モデルは `--model NAME` か設定ファイルの `ollama_model` で切り替えます（`"auto"` で翻訳先の言語による選択に戻ります）。

### 設定

よく変える設定は、左のペインの「設定...」にあります。「全般」ページの「写植」には、写植の最小と最大の大きさ、これより小さく組んだ訳文を見直しの一覧（レビュー）に入れる大きさ、
写植の大きさ（80〜200 %。100 % は吹き出しに収まる最大の大きさのままで、90 % ならすべての訳文を1割小さく組みます。
100 % より大きくしても、吹き出しと最大の大きさは超えず、ページ内で大きさをそろえるために抑えられていた訳文だけが大きくなります。
設定ファイルでは `text_scale`、本ごとの値は「編集」がオンのときのメニューの「この本の設定...」）、大文字で組むか、傾いた文字を同じ傾きで組むか、原文で大きく書かれた部分を訳文でも大きくするかが並びます。
「ダイアログ」には、ダイアログの文字の大きさ、ダイアログの配色（ライト、ダーク、Windows の設定に合わせる）、前に出た短いセリフの訳の使い回し、
「ビューアの右にインジケーター」（`see_through_indicators`。左のペインの「インジケーター」と同じもの）、「ポインターの下で待つ時間」（`hover_delay_ms`: 0〜3000 ミリ秒、既定は 450。範囲外の数は保存しません）が並びます。
最後が任意のページ用モデル（レイアウトモデルとインペイント）です。
「原文で大きく書かれた部分は訳文でも大きくする」（`size_emphasis`、既定でオン）: 原文で吹き出しの一部がほかより大きく書かれているとき（読み取りのときに文字の大きさを測ります。行単位で、ほかの 1.25 倍以上の部分）、
ページの訳文が確定したあとで、その部分を訳文の中で探します。訳文の言葉は一つも変わりません。まず日本語のその部分だけを訳し、訳文の中で探します。
見つからなければ、その部分に印を付けて吹き出しの行をもう一度尋ね、答えは訳文の中の言葉を指すためだけに使います（訳文に占める割合が日本語の部分の割合に見合い、その部分だけの訳とも合うときだけ採ります）。
ページの依頼とは別の、短い依頼が1回か2回で、そういう吹き出しのときだけです（テスト用の巻ではおよそ10ページに1つの吹き出しで、そういう吹き出し1つにつき約0.5秒）。テスト用のデータで代わりの部分を置いて測ると、見つけた言葉が正しかったのは12回に約11回で、半分ほどの部分で何かを見つけました。
見つかった部分は大きく写植します（原文より大きな倍率にはせず、最大で2倍。ほかの部分は読める大きさ `readable_font_size` より小さくせず、訳文全体を一つの大きさで写植したときの5分の4より小さくもしません）。吹き出しにそのように両方の大きさが収まらないときは、まず部分の倍率を下げ、ほかの部分の1.15倍を下回るなら吹き出しを一つの大きさで写植します。見つからなければ、吹き出しはこれまでどおりに写植します。
翻訳キャッシュはその部分を訳文の中の位置として保存します（日本語は保存しません）。そのため、キャッシュから表示したページでは何も尋ねません。設定をオフにすると、すべての訳文を一つの大きさで写植します。右のペインとコピーは、飾りのない文字のままです。
インペイント（絵の上の文字を LaMa で消して絵を補う）は「使わない」「GPU があるときだけ」「いつも使う（CPU でも）」から選びます。既定は「GPU があるときだけ」で、
モデルが入っていて、TASlation が使える GPU（CUDA が使える NVIDIA の GPU。PyTorch が CUDA で使えるもの）があるパソコンでだけ使います。
そうでないパソコンでは「使わない」と同じ消し方になり、このモデルを読み込むこともありません（その場合は、設定の欄にその旨を表示します）。
`install.cmd` は、NVIDIA の GPU があるパソコンには PyTorch の GPU 版（CUDA 版）を入れるので、そのまま「GPU があるときだけ」で使います。
GPU のないパソコン（AMD と Intel の GPU も GPU として数えません）、ドライバーが古いパソコン、GPU 版が動かなかったパソコンには CPU 版を入れ、そこでは使いません（docs/INSTALL.ja.md の「インストール」）。
この版より前のインストールで CPU 版が入っているパソコンでは、`install.cmd` を実行し直すと GPU 版に置き換えます。`update.cmd` のあとのインストールは置き換えず、そう表示します。
「いつも使う（CPU でも）」なら GPU がなくても使いますが、1画面に約4秒かかります（GPU では約0.6秒）。
レイアウトモデル（ふつうの検出が見落とす絵の上の文字を見つける）は「使わない」「インペイントと一緒のときだけ」「いつも使う」から選びます。既定は「インペイントと一緒のときだけ」です。
インペイントを使うパソコンで使うので、GPU のないパソコンや2つのモデルが入っていないパソコンでは、検出はこれまでと同じです。
0.2.0 より前の既定は「使わない」でした。選んだことがなければ新しい既定になります。設定ファイルに `detect_model = "off"` と書いてあれば（古い `taslation.toml.example` を写したファイルにもあります）、使わないままです。
どちらのモデルも、学習に使った画像の出どころを明らかにしていません（`docs/THIRD_PARTY.md`）。
2つのモデルは1つの質問でまとめて入れます（`install.cmd` が、その出どころのことを示してから尋ねます）。TASlation が GPU で LaMa を使うパソコン（GPU 版の PyTorch が入る、または入っているパソコン）では
Enter で入れ（[Y/n]）、それ以外では Enter で入れません（[y/N]）。コンソールのない実行では、どちらでも入れません（`-Yes` もこの質問には答えません）。
`python setup_models.py` を手で実行したときも同じように尋ね、Enter の意味は PyTorch が CUDA の GPU を使えるかどうか（「GPU があるときだけ」と同じ判断）で決めます。`--agreed` を付けると尋ねずに入れます。
「保存」を押すと `taslation.toml` に書き込み、すぐに反映します（表示中のページは、キャッシュから組み直します）。ファイルのコメントやほかの行は、そのまま残ります。
ダイアログの文字の大きさと配色は、保存するとすぐに変わります。
ダイアログの配色は「Windows の設定に合わせる」（既定。Windows の色の設定のアプリ モードに従います。TASlation の起動時に確かめます）、「ライト」（Windows の見た目）、「ダーク」
（ダイアログとそのタイトル バーを暗い地に明るい文字で表示します）から選びます。
左右のペインは、この2つの設定にかかわらず、色をビューアの地から、大きさをビューアのモニターの拡大率からとります。Windows のハイ コントラストがオンのあいだは、ダイアログはこの設定にかかわらず Windows の色を使います（設定の欄にもそう表示します）。
設定ファイルでは `theme`（`"system"`、`"light"`、`"dark"`）です。

「設定ファイルを開く」は、すべての設定が載った `taslation.toml` をテキストエディターで開きます。ファイルがなければ、先に `taslation.toml.example` から作ります。
作ったファイルでは、どの設定も行頭に `#` が付いた説明の状態で、`#` を消すとその設定が有効になります（既定値を書き込まないので、後のバージョンで既定値が変わっても、それに従います）。
作る場所は、設定を読み込む場所と同じです（読み込んだファイル、なければ状態フォルダの `taslation.toml`。状態フォルダは更新しても残ります）。
`update.cmd` で更新しても、TASlation のフォルダーにある `taslation.toml` は上書きしません（docs/INSTALL.ja.md の「更新」）。
ファイルで変えた設定は、次の起動から反映されます。

TASlation には、設定する自分のキーがありません。キーはすべてビューアに届きます。領域の編集画面の「前へ」「次へ」は Alt+↑ と Alt+↓、書式のコピーと貼り付けは
Ctrl+Shift+C と Ctrl+Shift+V です。以前の版でこれらに設定したキー（状態フォルダの `shortcuts.json`）はそのまま効きますが、変えるためのページはもうありません。

「設定」の「システム」ページには、ページの処理の段階（文字の検出、文字の読み取り、翻訳、消去と写植）ごとに、どこで動くか（「GPU（GPU の名前）」か「CPU」）と、1ページにかかった秒数を表示します。
検出は従来の検出が CPU で、レイアウトモデルを使うときはそのモデルが GPU で動きます。OCR は CPU で動くか、GPU に余裕があれば3つの読み手のうち2つが GPU で動き（`ocr_runs_on`、後述）、どちらでなぜかをその行に表示します。翻訳は Ollama が読み込んだモデルの場所で、
一部だけがビデオメモリーに載っているときは「GPU と CPU（60 % が GPU）」のように表示します（モデルが読み込まれていなければ、その旨を表示します）。
消去は紙の色の塗りつぶしが CPU で、インペイント（LaMa）を使うときは絵の上が GPU で動きます（「いつも使う（CPU でも）」で GPU がなければ CPU）。GPU として数えるのは CUDA が使える NVIDIA の GPU だけで、
調べるためにモデルを読み込んだり Ollama を起動したりはしません。秒数は最近写植した20ページの平均で、TASlation を終了するときに状態フォルダの `timings.json` に保存します（数値だけで、ページの内容は入りません）。
「もう一度調べる」で表示を更新します。同じ内容は `taslation doctor` も「Where each stage runs:」として出力します。その下に、このセッションでモデルに尋ねずに使い回した短いセリフの数を表示します（「短いセリフの使い回し」。数だけです）。
さらにその下の「翻訳モデルの GPU に置く層の数」（`ollama_num_gpu`）で、Ollama が翻訳モデルのどれだけを GPU に置くかを決められます。両方の翻訳器（PLaMo と Qwen）に効きます。
空欄（既定）は Ollama に任せ、要求はこれまでとまったく同じです。`0` は CPU だけで動かして GPU を空け（翻訳は数倍遅くなります）、数を入れるとモデルのその数の層を GPU に置き、残りを CPU で動かします。
Ollama の要求の `num_gpu` オプションとして送ります。保存すると次の要求から使います（すでに読み込まれているモデルは、そのために読み込み直しで少し待つことがあります）。
層の数を指定したときは、モデルが GPU と CPU に分かれていても読み込み直したり知らせたりしません（そう指定したためです）。空欄か 0〜999 の整数以外は保存しません。
その下の「OCR の実行場所」（`ocr_runs_on`）で、OCR の読み手をどこで動かすかを選べます。「空きがあれば GPU」（既定）、「CPU」、「GPU」の3つです（後述）。
今どこで動いていてなぜかは、上の OCR の行に出ます。保存すると、「CPU」と「GPU」は次のページから、「空きがあれば GPU」は次の起動から使います。
その下のチェックボックス「起動時に VRAM の空き容量が足りないときは、確認せずに一部を CPU で動かして起動する」（`gpu_short`）は、起動時の確認で GPU のメモリーが足りなかったときにどうするかです（後述の「GPU で動かすもの」）。
オフ（既定）では足りない量を表示して確認し、オンでは収まらないものを CPU で動かして起動します。次の起動から適用されます。
起動時に足りなかったときや、GPU でエラーが起きたものがあるときは、一覧の下にその旨と、CPU で動かしているものを表示します。
最後の「翻訳モデルのウィンドウキャッシュ」（`ollama_window_cache`）で、TASlation が起動する Ollama が翻訳モデルのウィンドウ全体のキャッシュを持つかどうかを決めます。
「使う」（既定）と「使わない」の2つです（後述）。次に Ollama が起動したときから適用され、いま動いている Ollama が使っているかどうかは、
上の翻訳の行に出ます（「TASlation が起動（ウィンドウキャッシュあり）」、または「なし」）。
その下のチェックボックス「TASlation の起動時に、1 日 1 回まで新しいバージョンを確認する」（`update_check`。既定はオフの `"off"`、オンは `"daily"`。インストーラーが1回だけ尋ねます）をオンにすると、
起動のたびに、前の確認から1日以上たっていれば、TASlation の準備ができて 30 秒以上たち、ページを読んだり翻訳したりしていないときに、別のプログラム `check_update.py` が GitHub に `CHANGELOG.md` の最初の 16 KB を問い合わせます。
新しいバージョンがあれば、「メニュー > ヘルプ」の「更新を確認...」の項目と、ステータス行の1行に出ます（ダイアログは出しません）。問い合わせられなかったときは何も表示しません。次の起動から適用されます。
「メニュー > ヘルプ > 更新を確認...」は、オンでもオフでも、選んだときに問い合わせます。答えから1分以内にもう一度選ぶと、その答えをもう一度表示し、問い合わせません（「問い合わせられなかった」ときは、すぐにまた問い合わせます）。今のバージョンと新しいバージョンを日付つきで、変更点とともに表示し、「今すぐ更新」で TASlation を閉じて
`update.cmd` が新しい版をダウンロードして更新し、TASlation をもう一度起動します（docs/INSTALL.ja.md の「更新」）。その画面にも同じチェックボックスがあります。
最後に確認した時刻と、そのとき見つかった最新のバージョンは、状態フォルダの `update-check.json` に残します（ほかには何も書きません）。git のクローンでは、起動時の確認はしません。

設定ファイル `taslation.toml` は、`--config` で指定したもの、実行したフォルダの `./taslation.toml`、状態フォルダ（`~/.taslation`、
または環境変数 `TASLATION_STATE_DIR` の場所）の `taslation.toml` の順に探し、最初に見つかったものを読みます（どれもなければ既定値）。
状態フォルダに置いてください。どのファイルを読んだかは `taslation doctor` が表示します。

作業ディレクトリかこのフォルダーに `taslation.toml` を置くと読み込みます（任意）:

```toml
ollama_model = "auto"        # "auto": PLaMo 3 Translate 2B, or Qwen3.5 4B for Brazilian Portuguese and Turkish; or a model of your own
ollama_num_ctx = 16384       # the chat translator's context window; PLaMo has its own (8192)
target_language = "English"
uppercase = false            # scanlation-style capitals (Latin script only)
size_emphasis = true         # the part the original letters larger is set larger in the translation too, where it is found there
readable_font_size = 11      # a translation set smaller than this is flagged "small" for review (0 = never)
text_scale = 1.0             # the lettering size (0.5-2.0): 0.9 a tenth smaller, 1.2 larger where the page held it back (a book can have its own)
enforce_terms = true         # a translation that misses a rendering from the series sheet is flagged "rendering"
spellcheck = false           # flag a word the dictionary does not know; its word lists (the pyspellchecker package) are an optional extra that TASlation does not install
take_columns_beyond = false  # dark bubbles: also read a column that goes on past the interior on the bubble's own black (a book setting too)
page_turn_wait_ms = 3000     # after a turn, a blank frame is looked at closely so long; a viewer behind other windows still blank then is raised once for a look
erase_mode = "fill"          # "fill": the bubble's own paper, flat or along its shading, within its outline;
                             # "inpaint": the same way, inpainted; "classic": the erase before 2026-10-30, byte for byte
art_erase = "auto"           # with "fill", lettering on the drawing is inpainted by LaMa once installed: "auto" only where PyTorch has a CUDA GPU (else as "off"), "lama" also on the CPU, "off"
detect_model = "auto"        # the layout model first, the classical detectors add what it missed: "auto" (where art_erase runs), "on", "off" (the default of earlier versions)
ollama_keep_alive = "5m"     # how long Ollama keeps the model after a request: "2h", "90s", seconds; "-1" never
                             # unloads, "0" unloads after every request
ollama_num_gpu = ""          # the model's layers on the GPU: "" Ollama decides, "0" the processor only, or a number
load_model_at_start = true   # TASlation loads the translation model at start, beside the OCR models; false: the first line to translate does
ollama_window_cache = "auto" # the Ollama TASlation starts: the cache of the model's whole window ("auto", "on"); "off": without it
ocr_threads = 0              # CPU threads for the OCR model (0 = torch's default, one per core); while
                             # other programs keep the CPU busy, half the cores can be faster
ocr_runs_on = "auto"         # "auto": two of the OCR readers where the check at the start puts them (the GPU when everything fits); "cpu"; "gpu"
gpu_short = "ask"            # the GPU's memory short at the start: "ask" (a box), or "processor" (what does not fit runs on the processor)
font_path = ""               # auto: the series sheet's font where installed, then models/fonts per script, then system fonts
reuse_lines = true           # a short line translated before in the book or its series gets that translation again
see_through_indicators = true  # the right pane: the bubble under the pointer, how far the page is, the status line
hover_delay_ms = 450         # the wait before a bubble under the pointer gives way to the original (0-3000; 0: at once)
update_check = "off"         # "daily": at the start, look for a new version at most once a day (check_update.py asks GitHub); "off": only Menu > Help > Check for updates...
```

ダイアログの文字の大きさは `ui_scale` で変えられます（1.0 が Windows の拡大率どおり。0.5〜3.0）。
効くのはダイアログだけです。左右のペインは、ビューアのモニターの拡大率に合わせます。

キーはすべて `taslation/config.py:Settings` のフィールドで、
`taslation.toml.example` に全項目と既定値が載っています。廃止した設定（`review_pass`、`series_notes`、
`notes_pages_per_request`、`revision_flag_distance`、`revision_changes_only`、`ollama_prompt_style` など）が設定ファイルに残っていても、読み込みはそのまま通り、何もしません。
TASlation の以前のウィンドウの設定（`see_through`、`next_page_key`、`prev_page_key`、`always_on_top`、`over_book`、`bubble_zoom`、`hover_shows`、`hover_reveal`、
`side_indicator`、`panel_font_size`）も同じです。それが残っている設定ファイルも読み込め、それらは除いて、ログに1行でそう書きます。
このバージョンが知らないキー（綴りの誤りや、新しいバージョンの設定）があっても、起動は止まりません。そのキーは読み飛ばし、TASlation が一度だけキーの名前を知らせます（値は表示しません）。
コマンドラインでは、そのたびに警告として表示します。旧名の `~/.selftrans` フォルダ（さらに古い
`~/.cleantrans` も）は初回起動時に `~/.taslation` へ移し、`SELFTRANS_*` 環境変数も、
`TASLATION_*` がなければ引き続き読み込みます。

### OCR モデルとそのライセンス

ページの文字は3つの OCR モデルが読みます（合わせて約 700 MB）。manga-ocr-charspot-small は文字を1字ずつ見つけて読むモデルで、
長い台詞に強い一方、文字のない絵からも何か読もうとします。そこで TASlation はまずこのモデルの確信度
（文字の中心らしさの平均と文字の見分けの確かさの平均の積。`ocr_min_confidence`、既定 0.65）と、
そのページのふつうの文字の大きさの3倍以下であること、2文字以上であることを確かめ、外れたものは文字ではないとして扱います。
1文字だけの台詞はこのため読み飛ばされます。そのときは「編集」をオンにして、領域を手で追加してください（「文字の領域を追加」）。手で追加した領域には、
この確認は一切かかりません。

確認を通った領域は manga-ocr-nar-small も読みます。2つの読みが同じならそれを採ります。違えば manga-ocr-base-CPT-flex も読み、
3つのうち、ほかの2つにいちばん近い読みを採ります（同点なら charspot、次に nar）。3つとも大きく違うときは、
その行に「TASlation が日本語を読み間違えたかもしれません」の確認フラグを立てます。手で追加した領域は3つのモデルがすべて読みます。

3つのモデルの重みのライセンスはどれも **CC BY-NC-SA 4.0** で、**非営利の利用に限られます**。TASlation のコードは MIT ですが、
ページを読むにはこれらのモデルが必要なので、TASlation を使うにはこの条件に同意する必要があります。`install.cmd` が条件を示して
1回だけ同意を尋ね、同意しなければ何もインストールせずに終了します（`-Yes` でも同意したことにはなりません）。重みはリポジトリには含まれず、
アプリケーションがダウンロードすることもありません。ダウンロードするのは `setup_models.py` だけです。

`setup_models.py` は、大きなファイルの進み具合をパーセントと MB で表示します。接続が途中で切れたときは、同じ実行の中で3回まで、
切れたところから続けます（サーバーが HTTP の Range に応じる場合。応じなければ最初から取り直します）。OCR モデル、ページ用モデル、
フォントは、失敗しても途中までのファイル（`.part`）を残し、次の実行で続きから取得します。続きから取ったファイルも、
ファイル全体のチェックサムを確かめてから置きます。PLaMo のファイルは、失敗したときや中止したときには途中までのファイルも消します
（TASlation からのインストールは何も残さないため）。失敗したダウンロードを3回試してから止まる `install.cmd` だけは、次の試しや次の実行が続きから進めるように、それを残します。サーバーが拒否したか、もう置いていないファイル（HTTP 401、403、404、410）は取り直さず、
終了コード 5 で終わります（もう一度実行しても変わらないため、TASlation を更新するか、プロジェクトの Issues ページを見るよう表示します）。winget で Python と Ollama を入れるときは、質問への Y を winget の
利用条件への同意として渡します（`--accept-source-agreements --accept-package-agreements`。質問の前にそう表示します）。

以前のインストールで manga-ocr-charspot-small しかない場合も、TASlation はそのモデルだけで動きます。ステータス行にその旨が1行出るだけで、
エラーにはなりません。`install.cmd` を実行すると残りの2つが入ります。

CPU で読むとき、OCR のモデルは `ocr_threads` の設定を共有します。CPU がほかの作業で
忙しいときは、`ocr_threads` をコア数の半分にすると速くなることがあります。
3つ目の OCR のモデルは1ページに数行しか読まないので CPU のままです。ほかの2つをどこで読むかは次の節のとおりです。

### GPU で動かすもの

NVIDIA の GPU があれば、TASlation は起動時に1回だけ、設定で GPU に置くものすべてがグラフィックボードのメモリーに収まるかを確かめます。
数えるのは、まるごと載せた翻訳モデル（ウィンドウキャッシュを使うときはその分も。後述）、3つの OCR の読み手のうち2つ（manga-ocr-charspot-small と manga-ocr-nar-small、`ocr_runs_on`）、使うときの LaMa とレイアウトモデル（高さが 1440 ピクセルを超える画面では文字がピクセルで大きいため、LaMa はより多く使います）、PyTorch 自身のメモリーで、そのときほかのプログラムが使っている分のほかに、約 700 MB が残ることが条件です。
この 700 MB は、グラフィックドライバーが空けておく分（これより少なくなると、そのとき計算していないプログラムのメモリーをパソコンの RAM に移し、そのプログラムは次の出番でそれを待つことになります）と、ほかのプログラムが増える分です。
確かめるのは法的な注意事項のあと、Ollama が応答してから、どのモデルも読み込む前です。ネットワークには何も問い合わせません（数値はこのパソコンのグラフィックボードと Ollama のものです）。

収まるときは、TASlation はすぐに使え、モデルはすべて裏で読み込みます。読み込み終わるまで右のペインに「モデルを読み込んでいます...」と出て、その間にビューアを選べます。それより前にめくったページは、必要なものがそろうまで待ちます。
「起動時に翻訳モデルを読み込む」がオフのときは、翻訳モデルはそれが必要な最初のページで読み込みますが、その分も起動時に数えます。
置いた場所はセッションのあいだ変えません。見直しも移動もしません。

足りないときは、何も読み込む前に次の画面が出ます。「VRAM の空き容量が N MB 不足しています。GPU を使っているほかのアプリケーションを閉じて「もう一度確認」を押すか、CPU モードで起動してください（遅くなります）。」その下に、CPU で動かすものを表示します。
「もう一度確認」（Enter）は、何かを閉じたあとにもう一度確かめます。「CPU モードで起動」は、収まらない分だけを CPU で動かして起動します。CPU に移す順番は OCR の読み手、LaMa、レイアウトモデルで、翻訳モデルは最後です。「終了」（Esc、または画面を閉じる）で TASlation を閉じます。
この順番は、失う時間の少ないものからです。OCR は翻訳と並行して読み（1ページ CPU で約 1.2 秒、GPU で約 0.6 秒）、LaMa は絵の上の文字だけを消し（1か所 CPU で約 1.7 秒、GPU で約 0.2 秒）、レイアウトモデルはどのページでも最初のセリフより前に動き（ページ単位で CPU で約 0.5 秒、GPU で約 0.06 秒）、翻訳モデルは CPU では約4倍遅く翻訳します。
「このコンピューターでは今後確認しない」にチェックを入れると、次からの起動では確認せずにそうします（`gpu_short = "processor"`。「設定...」の「システム」ページのチェックボックス「起動時に VRAM の空き容量が足りないときは、確認せずに一部を CPU で動かして起動する」がこの設定です）。
そのときは「システム」ページの一覧の下に、起動時にどれだけ足りなかったかと、このセッションで CPU で動かすものを表示します。
6 GB のグラフィックボードで既定の設定（PLaMo、両方のページ用モデル、高さ 1440 ピクセルまでの画面）なら、起動時にほかのプログラムが約 1.7 GB より多く使っているとこの画面が出ます（それより高い画面では約 1.4 GB）。大きいほうの翻訳モデル（Qwen3.5 4B）は、6 GB のボードでは OCR の読み手やページ用モデルと一緒には収まりません。

NVIDIA の GPU がないパソコンでは、この画面は出ません。尋ねることのできない `taslation` コマンドと開発用のツールでも出ず、「CPU モードで起動」と同じようにします。
`ocr_runs_on` の `"cpu"` と `"gpu"`、`ollama_num_gpu` の層の数は、空きにかかわらずその部分をその場所に置きます。そうして GPU に置いたものがあるときは確認しません。設定どおりに起動し、どれだけ足りないかを「システム」ページに表示します。

起動のあとでほかのプログラムが使うメモリーは、そのプログラムのものです。TASlation は見直しません。Windows ではグラフィックボードのメモリーを超えて使ってもエラーにはならず、遅くなります。ドライバーがメモリーを移し替え、読み取りと翻訳がそれを待つためです（6 GB のボードでは要求の始まりが 0.2〜0.5 秒遅れ、ほかのプログラムがボードで計算しているときは OCR が CPU より遅く読みました）。そのあいだも「システム」ページは GPU と表示します。ほかのプログラムを閉じるか、TASlation を起動し直すと、改めて確かめます。
ある部分が GPU で失敗したとき（メモリー不足、CUDA のエラー）は、その部分はセッションの終わりまで CPU で続け、ページはいつもどおり仕上がり、「システム」ページにその旨を表示します。読みはどちらでも同じです。
翻訳モデルが答えている間（見開きの次のページをその間に読むときなど）は、OCR の読み手の2つも CPU で読みます。GPU では翻訳モデルの計算を待つことになり、1行に 0.7 秒かかるためです（CPU なら 0.13 秒）。

Ollama のモデルは必要なあいだだけ GPU メモリに載せます。TASlation は起動時に、OCR モデルの読み込みと並行してモデルを読み込むので（`load_model_at_start = true`、既定。
「設定...」の「システム」ページの「起動時に翻訳モデルを読み込む」）、最初に翻訳するページはその読み込みを待ちません。この読み込みは何も表示せず、
Ollama が動いていないときやモデルが入っていないときは何もしません（モデルが必要な最初のページが、これまでどおり何が問題かを伝えます）。
この設定がオフのときと `taslation` コマンドでは、翻訳が必要な行が出たときに読み込みます
（数秒かかり、状態表示に出ます）。翻訳がキャッシュにあるページでは読み込みません。読み込んだモデルは最後の要求（または起動時の読み込み）から
`ollama_keep_alive`（既定 "5m"）の間残り、そのあと自動で解放されます。`ollama_keep_alive = "0"` のときは起動時に読み込みません。未翻訳のページを読み進めている間は要求のたびに
延長されるので、ページごとに読み込み直すことはありません。TASlation を終了したときと、`taslation` コマンドの処理の終わりには、すぐに解放します。
ページを読んでいて何も翻訳していない間は、Ollama がまだ持っていなければ、次のページの最初の要求の頭（シリーズシートと、その要求が始まる前の行）を Ollama に計算させておきます（前の行が新しいものだけに切り詰められたあとなど）。次にめくった未翻訳のページはその分（1 秒ほど）を待ちません。
その要求が送るのと同じものを送り、答えは何も残さないので、要求はこれがないときと同じです。ただし、Ollama が要求を別の途中から計算するときと同じく、モデルが行をわずかに違う言い回しにすることがあります（テスト用のデータでは10行に1行ほど。点数はほぼ同じでした）。何も表示せず、モデルがすべてグラフィックボードに載っているときだけ行い、ページをめくるとすぐやめます。
`ollama_keep_alive = "-1"` にすると以前と同じく、起動時に OCR モデルより先に読み込み、解放しません。
読み込んだモデルの一部しかグラフィックボードに載らなかったときは、その旨を知らせます（読み込み直しはしません）。
ゲームなどほかのプログラムのために GPU のメモリーをすぐ空けたいときは、「メニュー > モデルを今すぐ解放」を使います。TASlation がこのセッションで読み込んだか使った翻訳モデルを、
Ollama の API の通常の要求（そのモデルに `keep_alive` 0）で解放し、ページ用モデル（レイアウトモデルと LaMa）もメモリーを返します。`ollama_keep_alive = "-1"` のときも解放します。
ほかのプログラムが同じ Ollama に読み込んだモデルには触れず、Ollama 自体を止めたり起動したりもしません。GPU に置いた OCR モデルは CPU に戻り（次のページで、起動時の確認で決めた場所に戻ります）、
ページ用モデルか OCR を一度 GPU で動かしたときに PyTorch が作った CUDA のコンテキスト（数百 MB）は、TASlation を終了するまで残ります。
何を解放したかはステータス行に出ます（GPU に置いていた OCR のメモリーも、返したときはそう出ます）。翻訳中や、翻訳が始まるのを待っている間は解放せず、その旨をステータス行に出します。
起動時の読み込みがまだ終わっていなければ、それを待ってから解放します。次に翻訳が必要な行が出たときは、いつもどおりモデルを読み込み直します。
Ollama は、TASlation が使うあいだだけ動きます。翻訳するときに Ollama が動いていなければ、TASlation は Ollama のサーバー（`ollama serve`）を
表示しないウィンドウで起動し（Ollama のアプリは起動しません）、起動したことを状態フォルダーの `ollama-started.json` に書き残します
（プロセスの番号、プログラム、起動した時刻、使っている TASlation だけで、本の文字は入りません）。TASlation を終了したとき、または翻訳した `taslation` のコマンドが終わったときに、
その Ollama を止めます。ほかの TASlation がまだ使っているときと、ほかのプログラムのモデルが読み込まれているときは止めません（後のほうは、それからは TASlation のものとして扱いません）。
止まらなかったときは記録を残し、次に TASlation が終わるときに止めます。TASlation が途中で落ちて Ollama が残ったときは、次に TASlation が使うときに引き継ぎます。
自分で起動した Ollama（スタートメニューから、または `ollama serve`）は、TASlation が起動したものではないので止めません。
「翻訳プログラムが起動しませんでした」などの表示でパソコンを再起動するよう勧めるのは、応答しなくなった Ollama を確実に終わらせるためです。再起動のあとは、TASlation が翻訳するときに改めて起動します。
TASlation が起動する Ollama には、環境変数を3つ渡します。TASlation 自身の環境にない変数は、Windows がこのユーザー（またはこのパソコン）に保存している値を、
それもないときだけ TASlation の値を渡します。設定されている値は変えません。
NVIDIA の GPU のメモリが 6 GB 以下なら、`OLLAMA_KV_CACHE_TYPE` は `q8_0` です（Ollama が GPU のメモリーを節約します）。
`LLAMA_ARG_SWA_FULL=1` で llama.cpp は翻訳モデルのウィンドウ全体のキャッシュを持ち、要求ごとにプロンプト全体を計算し直さずに前の要求の続きから計算します。
`LLAMA_ARG_CACHE_RAM=256` で以前の要求 256 MB 分を RAM に置きます（この変数がないと Ollama はそれに最大 8 GB 使います）。
TASlation の 6 GB の GPU での測定では、この2つで翻訳の時間が約4分の1減り（214 ページを一度に通して訳して 401 秒が 296 秒、GPU なしで1行 1.28 秒が 0.98 秒）、
モデルの GPU メモリーは 130 MB 増えました（Ollama 既定の KV キャッシュでは 220 MB）。
どうするかは設定「翻訳モデルのウィンドウキャッシュ」（`ollama_window_cache`）で決めます。「使う」（既定。ファイルでは `"auto"` か `"on"`）では両方を渡し、
「使わない」（`"off"`）では `LLAMA_ARG_CACHE_RAM=0` だけで、これまでどおりです。起動時の確認は、ウィンドウキャッシュの分（130 MB）も含めて翻訳モデルを数えます（この節の初め）。
OCR の読み手を GPU に残すためにウィンドウキャッシュを外すことは、もうしません。どうしたかは、Ollama を起動するたびにログに1行出し、
「システム」ページと `taslation doctor` の翻訳の行にも出ます。
前からある Ollama には、`install.cmd` が `LLAMA_ARG_CACHE_RAM=0` と、GPU が 6 GB 以下なら `OLLAMA_KV_CACHE_TYPE=q8_0` を、この Windows ユーザーの環境変数として設定します
（docs/INSTALL.ja.md の「インストール」。自分の Ollama にウィンドウキャッシュを使わせる方法もそこにあります）。Windows がそれを保存しているので、そのパソコンで TASlation が起動する Ollama も
`LLAMA_ARG_CACHE_RAM=0` になり、RAM の 256 MB なしでウィンドウキャッシュを使います（上の測定で 296 秒の代わりに 317 秒）。

### 本がなくても試すには

`install.cmd` のあるフォルダで PowerShell から `.\.venv\Scripts\python.exe tools\fake_viewer.py` を実行すると（ソースのチェックアウトでは `python tools/fake_viewer.py`）、合成したテストページを表示する代用のビューアが開きます（そのウィンドウで左矢印を押すと次のページ）。
TASlation で「Fake Viewer」というタイトルのウィンドウを選び、そちらでページをめくると、取り込み、翻訳、
その上の写植が一通り動くことを確かめられます。

### エラーの記録と「詳細をコピー」

TASlation は、状態フォルダの `log.txt` にエラーを記録します（大きくなると次のファイルに移り、古いものから消えるので、全部で 1 MB ほどです）。
起動時の動作環境（TASlation のバージョンと日付、Python、Tk、Windows、torch とグラフィックボード、Ollama のバージョン）、既定値から変えた設定の名前と値、
警告、エラーとその発生箇所（プログラムのファイル名と行）を書きます。
ページの文字、OCR の結果、訳文、書名、ウィンドウのタイトルは書きません。ファイルの場所は、状態フォルダやモデルのフォルダを名前（`<state dir>` など）で書くだけで、
その先のファイル名や、ほかの場所は `<path>` に置き換えます。エラーの文中の引用や、ASCII 以外の文字（日本語など）は `…` に置き換えます。

「メニュー > ヘルプ > TASlation について」と、エラーを知らせる画面にある「詳細をコピー」は、同じ内容（動作環境、変えた設定、最後のエラー）に
オフライン保護の状態（有効か無効か、接続できるこのパソコンの Ollama のアドレス、遮断した接続の試みの回数）を加えて、クリップボードに入れます。
不具合を報告するときに貼り付けてください。どこにも送信しません。起動できなかったときの画面でも、「はい」でコピーできます。

## オフラインで動くことを自分で確かめる

保護が及ぶのは TASlation 自身のプロセス、つまりスタートメニューから始まるもの（`taslation gui`）とすべての `taslation` コマンドです。重い部分を読み込む前に、このパソコン（ループバック）の Ollama のポート（既定 11434）あて以外の
接続と名前解決をすべて失敗させ、モデルを読み込むライブラリにはオフラインで動くよう指示します。
ほかのプログラムには及びません。翻訳を受け持つ Ollama は別のプログラムです。TASlation は、Ollama のサーバーが動いていなければ起動し（`ollama serve`。使わなくなれば TASlation が止めます）、127.0.0.1 で、
翻訳モデルの読み込みと解放、TASlation が送る行の翻訳を頼みます（`/api/generate`、`/api/chat`、`/api/ps`、`/api/tags`、`/api/version`）。`ollama` コマンドでモデルの一覧を取り、
あなたが同意したときには要らなくなったモデルを削除します（`ollama list`、`ollama rm`）。ダウンローダーは、翻訳モデルの取得や取り込みを頼みます
（`ollama pull`、`ollama create`）。Ollama がそのほかに何をするかは、TASlation の管理の外です。
ダウンローダー（`setup_models.py`。モデルのダウンロードに同意したとき、TASlation とコマンドラインが別のプロセスとして実行します）とインストーラー（`install.cmd`。`update.cmd` も実行します）は、ダウンロードをするので、保護なしで動きます。
3つ目は、新しいバージョンを確認するプログラム `check_update.py` です。あなたが「メニュー > ヘルプ > 更新を確認...」を選んだときと、起動時の確認をオンにしたときに、TASlation が別のプロセスとして実行し、
`update.cmd` も、新しい版を探してダウンロードするよう求められたときに実行します。これも保護なしで動き、TASlation のパッケージからは読み込まれません。
問い合わせるのは GitHub の3つのホストだけです。raw.githubusercontent.com には `CHANGELOG.md` の最初の 16 KB を（Range ヘッダーでその部分だけを求めるので、ファイルがどれだけ長くなっても問い合わせはこの大きさのままです）、github.com にはその版の ZIP を HTTPS の GET で求め
（ZIP は、途中で切れたときと、届いたものがすべての項目を読み直して完全な ZIP でなかったときに、3回まで試します。完全でなかったものは、最初からダウンロードし直します）、github.com は ZIP を codeload.github.com へ回します。ほかのアドレスへ回されたときは、そこへは問い合わせずに止まります。
HTTP に要る決まりのヘッダーとその Range ヘッダーのほかに送るのは、決まった User-Agent（`TASlation-update-check`）だけで、問い合わせの文字列、Cookie、入っているバージョン、このパソコンや本のことは送りません。
GitHub に見えるのは、どのサイトを開いたときとも同じく、IP アドレスと時刻です。プロキシは使いません。
TASlation のプロセス自体はどこにも接続しないので、`taslation audit` が示す TASlation 自身の通信は、これがあっても変わりません。

`install.cmd` でインストールした場合、TASlation のプログラムは `install.cmd` のあるフォルダの `.venv\Scripts\taslation.exe` です。PATH には入っていません。
そのフォルダで PowerShell を開き（エクスプローラーでそのフォルダを開いたまま、アドレスバーに `powershell` と入力して Enter）、次を実行します。

1. `.\.venv\Scripts\taslation.exe doctor` が、出力の中に
   `Network guard: ON (loopback:11434 only; 0 attempt(s) blocked)` を出すことを確かめます。
   TASlation では「メニュー > ヘルプ > TASlation について」の「詳細をコピー」で、同じ状態を `Offline guard: on; ...` の行としてコピーできます。右のペインに表示が出るのは、
   保護が接続の試みを遮断したときだけです（その後は TASlation を終了するまで残ります）。
2. `.\.venv\Scripts\taslation.exe audit tests\fixtures\sample_page.png --translator echo` は、
   TASlation に付いている見本のページで検出と OCR を実行し（翻訳は何も送らない代わりの翻訳器が受け持ちます）、プロセスが行ったネットワーク通信をすべて表示します。
   `--- network audit ---` の下に `allowed calls: none (no network call at all)` と `blocked attempts: none` が出ます。
   最後の `--- saved files (at rest) ---` は、データフォルダにある本の文字を含む保存ファイルを数え、すべて保護されていれば `plain files with text of a book: none` で終わります。何も変更しません。
3. 同じコマンドを `--translator echo` なしで実行すると、Ollama でページを翻訳します（動いていなければ起動し、終わりに止めます）。
   許可された通信として表示されるのは、`127.0.0.1` のポート `11434` の名前解決と接続だけです（モデルを読み込む要求と、ページの要求のため）。
4. Wi-Fi を切るかケーブルを抜いて、いつもどおりに使ってください。Ollama は応答を続け、OCR モデルとページ用モデルは
   `models\` から読み込まれます。

開発用のツールを入れたソースのチェックアウト（`pip install -e .[dev]`）では、テストがネットワークの保護と保存ファイルの保護を確かめます。
`python -m pytest tests/test_netguard.py -q`（名前解決、直接の接続、UDP、Ollama 以外のループバックのポートを拒み、生のソケットのモジュールを使う子プロセスを監査フックが止めること）と、
`python -m pytest tests/test_protect.py -q`（Windows のデータ保護で、一時フォルダの中で）です。

`docs/OFFLINE_VERIFICATION.md` に、手順と、開発時に行った検証の結果を記録しています。

## 仕組み

詳しくは `docs/ARCHITECTURE.md` を参照してください。概要: 320ビットの知覚的なページ指紋で画面のページを識別し（見開きなら1ページずつ。指紋はそのページの紙の上の墨の範囲で、暗い背景のビューアではページの大きな明るい部分とそれに並ぶものを紙とみなします。範囲の中の文字はどれも、その上か下か隣にあるページのものとして扱います）、
キャッシュにあれば保存した訳文をライブのページに重ねます。なければ、文字の検出（インペイントが動くパソコンではレイアウトモデルと OpenCV による従来の検出、それ以外では OpenCV だけ）、OCR、
Ollama のモデルによる翻訳（シリーズ設定と直前のページを文脈に。PLaMo は1行ずつ、Qwen はページごとに1回）、消去と写植を行い、得られた訳文をキャッシュに保存します。
プログラムのアイコンは `tools/make_icon.py` が
Pillow だけで描き、`taslation/ui/assets/` に置いています。絵を変えたら実行し直してください。

## 制限事項

* インペイントが動くパソコン（既定では、PyTorch が CUDA で使える NVIDIA の GPU があり、ページ用モデルを2つとも入れたパソコン。「設定」の「レイアウトモデル:」と「インペイント:」）では、レイアウトモデルが先に文字を見つけ、従来の画像処理がその見落としを加えます。それ以外のパソコンでは、検出は従来の画像処理だけです。
  従来の検出の対象は、閉じた吹き出しと枠（明るいものも暗いものも。暗い吹き出しや暗い部分の明るい文字は白で写植します）と、
  ページに直接書かれた台詞や効果音です。ページに直接書かれた文字は、文字とその周りの明るい背景だけを消し、細い線や網点も含めて隣の絵は残し、
  空いた所に訳文を組みます。絵が近いと訳文は小さくなり、文字の一部と取り違えた小さな絵は一緒に消えます。
  同じ濃さの込み入った絵に入り込んだ文字は、従来の検出では見落とします。`translate_sfx = false` にすると、
  手描きの効果音は描かれたまま残します。レイアウトモデルとそのライセンス、学習データについてモデルのカードが述べていることは `docs/THIRD_PARTY.md` にあります。
* 接したり重なったりして1つの白い部分になっている吹き出しは、くびれた所や、輪郭線が両側から鋭く内側に曲がる所で切り分け、それぞれ別に訳します。
  2つのセリフがずれて並んでいても、それぞれの行どうしより離れていれば同じように切り分けます。
  1つの吹き出しに2組の列がある場合は1つの領域のままです（`split_joined_bubbles`、この本の設定でも変えられます）。
  2つの領域の枠が重なる所では、それぞれの訳文を自分の日本語に近い側に置くので、訳文どうしが重なりません。キャッシュのページも表示するときにそうなります。
  以前のバージョンでキャッシュしたページは、接した吹き出しの組に訳文を1つしか持たないので、丸い矢印（キャッシュを使いません）で訳し直してください。
* OCR の精度は文字の大きさにほとんど左右されません（きれいな縦書きなら 12 px も 28 px と同じように読め、
  切り出しを拡大しても変わりません）。精度を下げるのは、スクリーントーンの上の文字、装飾的な書体、そもそも文字ではない領域で、これらは検出の問題です。
* 消去は吹き出しの輪郭線の内側にとどまり、吹き出しの紙の色（クリーム色や陰影も）で塗るので、
  アンチエイリアスで途切れた細い輪郭線を塗りつぶすことはありません（テスト用の巻では、吹き出しの外で変わった画素が67,624から19,882に、
  途切れた輪郭線の画素が13,398から166に減りました）。`erase_mode = "classic"` で以前の消去方法に戻せます。
  輪郭線そのものに描き込まれた文字、輪郭のはっきりしない部分（インクの飛び散りなど）、小さな吹き出しの1〜2文字は消し残すことがあります。
* OCR モデルが当て推量でしか読めない領域（顔、ハイライト、読めない効果音）は、確信度のフィルター（`ocr_min_confidence`）で捨てます。小さな領域（`min_short_bubble`、
  60 px 未満）の1〜2文字は絵の点などとみなしますが、確信度0.95以上で、ひらがなか漢字で始まり、
  輪郭線のある吹き出しにある短い台詞は訳します。小さな領域のカタカナ（ほとんどは描き文字の効果音の一部）と、単独の記号（感嘆符、
  三点リーダー）は描かれたまま残します。
* 取り込むのはページの部分だけにしてください（ブラウザで読むビューアなら、
  ブラウザのタブとアドレスバーを除けば十分です。リーダー自身のツールバーは自動で無視します）。見開きは2ページに分けます。暗い背景のビューアでは、下半分が黒いコマのページでも、明るい部分と並ぶ吹き出しやコマまでを1ページとして取り、リーダーのスライダーやボタン、帯は取り込みません。ページの端がビューアと同じ黒だとそこだけページの外になりますが、その文字は隣のページの一部として読みます。範囲の中でどのページにも属さない文字は最も近いページのものとして読むので、リーダー自身の帯は範囲から外してください。リーダーがヘッダーやページスライダーをページの上に表示している間は、帯ごと読むのでページ指紋が変わります。
* 内側にスクリーントーンや暗い色がある吹き出し、輪郭線が途切れた吹き出しは、見落とすことがあります。
* 訳の質は Ollama のモデル次第です。大きなモデルほど上手で、そのぶん遅くなります。
  モデルが苦手な言語では訳が劣ります。
* 名前の表記はシリーズ設定に書いたときだけそろいます。書いていない名前は、モデルが行ごとに読むので、表記が揺れることがあります。
  要確認の印や「検索と置換...」で見つけて、シリーズ設定に加えてください。
* ページ指紋はウィンドウの大きさやビューアの背景の違いには強いものの、
  単ページ表示と見開き表示の切り替えには対応しません（見開きは2ページに分けるので、見開きで訳したページは単ページ表示でも見分けられますが、
  逆はできません）。
* 取り込みは Windows 専用です。ほかの OS では `translate` コマンドで画像ファイルを処理できます。
